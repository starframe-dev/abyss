# Спецификация: `internal/js/dom.go`

## Назначение

Пакет `js` реализует состояние моста DOM для JavaScriptCore: хранит узлы документа и их ID, состояние активного контекста, стили, layout, обработчики событий, таймеры и флаг необходимости перерисовки. Файл сам по себе не содержит C-функций-обёрток для вызова JS; он использует типы JavaScriptCore через cgo и `Context` из пакета.

## Типы

- `NodeID` — целочисленный ID DOM-узла.
- `Rect` — прямоугольник с полями `X`, `Y`, `Width`, `Height` типа `float64`.
- `Runtime` — снимок состояния страницы: контекст и URL, карты узлов и обратных ID, корень документа, стили, layout, слушатели и контекст событий, dirty-флаг и таймеры.
- `timer` — ID, защищённая ссылка на callback, deadline, интервал и признак повторения (`Repeat`).

## Состояние и синхронизация

Глобальное состояние разделено по мьютексам: `nodeMu`, `computedStylesMu`, `layoutBoxesMu`, `eventMu`, `currentCtxMu`, `dirtyMu` и `timerMu`. Оно включает карты `nodes` и `nodeIDs`, счётчик `nodeNextID`, `rootDoc`, кэши `computedStyles` и `layoutBoxes`, события `eventListeners`/`eventCtx`, текущие `currentCtx`/`currentURL`, флаг `dirty`, а также `timers`/`nextTimerID`. `Runtime` хранит соответствующие данные отдельной страницы, когда она отсоединена.

## API и поведение

### Контекст и состояние runtime

- `SetCurrentContext(ctx, url)` сохраняет текущие контекст и URL. Если прежний контекст ненулевой и отличается от нового, сначала сбрасывает систему событий и закрывает прежний контекст.
- `GetCurrentContext()` возвращает пару текущих контекста и URL под блокировкой.
- `CaptureRuntime()` отсоединяет и переносит в новый `Runtime` все перечисленные состояния. Вызывающая сторона должна сериализовать операцию с выполнением JavaScript.
- `ActivateRuntime(runtime)` восстанавливает снимок; для `nil` ничего не делает. Карты узлов и слушателей при необходимости инициализируются пустыми. Вызов требует, чтобы другой runtime не был активен и выполнение моста было сериализовано.
- `CloseRuntime(runtime)` для ненулевого снимка активирует его и закрывает текущее состояние.
- `CloseCurrentContext()` сбрасывает систему событий и закрывает ненулевой контекст, очищает контекст/URL, затем сбрасывает DOM, стили, layout и dirty-флаг.

### Dirty-флаг

`SetDirty`, `IsDirty` и `MarkClean` под блокировкой устанавливают, читают и очищают флаг `dirty` соответственно.

### DOM и ID

`InitDOM(doc)` сбрасывает DOM-состояние, создаёт карты узлов, устанавливает `nodeNextID` в 1 и `rootDoc`, затем рекурсивно регистрирует документ и потомков. Регистрация прекращается при `nil` или достижении `dom.MaxDOMNodes`; ID выдаются из `nodeNextID`. `assignIDs` и `assignIDsToNew` обходят дерево рекурсивно.

`createElement` создаёт элемент с именем тега в нижнем регистре, пустыми атрибутами и детьми; `createTextNode` создаёт текстовый узел; `createDocumentFragment` создаёт фрагмент с типом `DocumentFragmentNode` и именем `#document-fragment`. Все три регистрируют узел и возвращают `nil`, если достигнут лимит.

`appendChild(parentID, childID)` ничего не делает при отсутствующих узлах, попытке добавить узел к самому себе или создать цикл. Фрагмент распаковывается: его дети переносятся к родителю, а список детей фрагмента очищается. Обычный ребёнок сначала отсоединяется от прежнего родителя, затем добавляется к новому.

`removeChild(parentID, childID)` удаляет ребёнка только если он присутствует в списке `parent.Children`, после чего очищает его `Parent`.

`setInnerHTML(id, html)` ищет узел, разбирает строку посредством `dom.ParseFragment`, отсоединяет прежних детей, затем добавляет непосредственных детей фрагмента и назначает ID новым узлам. При неизвестном ID ничего не делает.

`setAttribute(id, name, value)` устанавливает атрибут с именем в нижнем регистре, создавая карту атрибутов при необходимости. `setTextContent(id, text)` при существующем узле и свободном месте в лимите узлов очищает детей и добавляет новый текстовый узел с родителем `node`; при превышении лимита ничего не меняет.

### Чтение DOM

- `getBody()` ищет `html` среди непосредственных детей `rootDoc`, затем `body` среди детей `html`; возвращает `nil`, если не найден.
- `getElementByID(id)` обходит дерево от `rootDoc` в порядке обхода в глубину и возвращает первый элемент с соответствующим атрибутом `id`.
- `getNodeID(n)` возвращает ID из обратной карты `nodeIDs` или `-1`.
- `getAttribute(id, name)` возвращает атрибут найденного узла через `GetAttr`; для неизвестного ID возвращает пустую строку.

### Внутренние операции

`removeNodeFromParentLocked` удаляет узел из списка прежнего родителя и требует удержания `nodeMu`. `moveAllChildren` переносит копию списка детей из source в parent, обновляет `Parent` и очищает `source.Children`; вызывающий код удерживает `nodeMu`. `wouldCreateCycle` проверяет, встречается ли child среди предков parent.

## Ограничения и синхронизация

Операции над узлами и ID используют `nodeMu`; состояние стилей, layout, событий, контекста, dirty-флага и таймеров защищается соответствующими мьютексами. `CaptureRuntime` и `ActivateRuntime` перемещают ссылки и срезы состояния, а не копируют содержимое. Вызов `getBody` напрямую не берёт `nodeMu`, поэтому вызывающая сторона должна обеспечить необходимую сериализацию. Функции манипуляции DOM не вызывают `SetDirty` автоматически. Создание узлов и присвоение ID ограничены `dom.MaxDOMNodes`.
