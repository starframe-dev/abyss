# Спецификация bridge_dom.go

## Обзор

Файл `bridge_dom.go` реализует мост (bridge layer) между Go и JavaScriptCore для манипуляций DOM-деревом. Он предоставляет набор функций, которые вызываются из JavaScript и выполняют операции с элементами DOM через C-интерфейс JavaScriptCore.

## Архитектура

### Слой моста

Файл работает как адаптер, преобразующий JavaScript-вызовы в операции с внутренним представлением DOM в Go. Ключевые компоненты:

1. **C-интерфейс JavaScriptCore** — используется через внешние функции из bridge.c
2. **Контекст исполнения** — структура `Context` из соседнего пакета
3. **ID-система узлов** — внутреннее представление узлов через числовые ID (отрицательные значения указывают на ошибки)

### Внешние зависимости

```c
#include <JavaScriptCore/JavaScriptCore.h>
#include <stdlib.h>

extern JSObjectRef makeGoFunction(JSContextRef ctx, const char* funcName);
extern JSType _getType(JSContextRef ctx, JSValueRef value);
extern char* _valueToString(JSContextRef ctx, JSValueRef value, JSValueRef* exception);
extern JSValueRef _makeArray(JSContextRef ctx, JSValueRef* values, size_t count, JSValueRef* exception);
extern void _fprintf_stderr(const char* msg);
extern void _protectValue(JSContextRef ctx, JSValueRef value);
extern void _unprotectValue(JSContextRef ctx, JSValueRef value);
extern JSValueRef _callAsFunction(JSContextRef ctx, JSObjectRef func, JSObjectRef thisObj, size_t argCount, const JSValueRef args[], JSValueRef* exception);
extern JSValueRef _makeString(JSContextRef ctx, const char* value);
extern JSValueRef _makeBoolean(JSContextRef ctx, bool value);
```

## Публичный API

Все функции имеют одинаковую сигнатуру и возвращают `C.JSValueRef`:

```go
func <FunctionName>JS(ctx *Context, args []C.JSValueRef) C.JSValueRef
```

### Функции создания элементов

#### createElementJS

Создаёт HTML-элемент по имени тега.

**Параметры:**
- `ctx *Context` — контекст исполнения JS
- `args []C.JSValueRef` — массив аргументов JS
  - `args[0]` — строка имени тега (например, "div", "span")

**Поведение:**
1. Проверяет наличие минимум одного аргумента
2. Если аргумент пустой, использует "div" по умолчанию
3. Создаёт элемент через внутреннюю функцию `createElement`
4. Возвращает JS-обёртку узла через `nodeToJS`

**Возвращаемое значение:**
- `C.JSValueRef` — обёрнутое JS-значение узла
- При ошибке (недостаточно аргументов): `JSUndefined`

---

#### createTextNodeJS

Создаёт текстовый узел.

**Параметры:**
- `args[0]` — строка текста

**Поведение:**
1. Проверяет наличие аргумента
2. Создаёт текстовый узел
3. Возвращает JS-обёртку

**Возвращаемое значение:**
- `C.JSValueRef` — обёрнутый текстовый узел
- При ошибке: `JSUndefined`

---

#### createDocumentFragmentJS

Создаёт фрагмент документа.

**Параметры:**
- Без аргументов

**Поведение:**
1. Создаёт фрагмент документа
2. Возвращает JS-обёртку

**Возвращаемое значение:**
- `C.JSValueRef` — обёрнутый фрагмент

---

### Функции манипуляции с содержимым

#### appendChildJS

Добавляет узел как последнего ребёнка.

**Параметры:**
- `args[0]` — ID родительского узла
- `args[1]` — ID добавляемого узла

**Поведение:**
1. Проверяет наличие 2 аргументов
2. Преобразует JS-аргументы в ID узлов
3. Проверяет валидность ID (отрицательный = ошибка)
4. Вызывает `appendChild`
5. Инвалидирует CSS-кэш через `css.InvalidateCache()`
6. Помечает состояние как "грязное" через `SetDirty()`

**Возвращаемое значение:**
- `C.JSValueRef` — добавленный узел (args[1])
- При ошибке: `JSUndefined`

---

#### insertBeforeJS

Вставляет узел перед указанным референсным узлом.

**Параметры:**
- `args[0]` — ID родительского узла
- `args[1]` — ID нового узла
- `args[2]` — ID референсного узла

**Поведение:**
1. Проверяет наличие 3 аргументов
2. Преобразует аргументы в ID
3. Проверяет валидность parentID и newNodeID
4. Вызывает `insertBefore`
5. Помечает состояние как "грязное"

**Возвращаемое значение:**
- `C.JSValueRef` — вставленный узел (args[1])
- При ошибке: `JSUndefined`

---

#### replaceChildJS

Заменяет существующий узел на новый.

**Параметры:**
- `args[0]` — ID родительского узла
- `args[1]` — ID нового узла
- `args[2]` — ID старого узла

**Поведение:**
1. Проверяет наличие 3 аргументов
2. Преобразует аргументы в ID
3. Проверяет валидность всех трёх ID
4. Вызывает `replaceChild`
5. Помечает состояние как "грязное"

**Возвращаемое значение:**
- `C.JSValueRef` — заменённый/удалённый узел (args[2])
- При ошибке: `JSUndefined`

---

#### removeChildJS

Удаляет узел из родительского элемента.

**Параметры:**
- `args[0]` — ID родительского узла
- `args[1]` — ID удаляемого узла

**Поведение:**
1. Проверяет наличие 2 аргументов
2. Преобразует аргументы в ID
3. Проверяет валидность обоих ID
4. Вызывает `removeChild`
5. Инвалидирует CSS-кэш
6. Помечает состояние как "грязное"

**Возвращаемое значение:**
- `C.JSValueRef` — удалённый узел (args[1])
- При ошибке: `JSUndefined`

---

#### setInnerHTMLJS

Устанавливает содержимое HTML элемента.

**Параметры:**
- `args[0]` — ID элемента
- `args[1]` — строка HTML

**Поведение:**
1. Проверяет наличие 2 аргументов
2. Преобразует ID узла
3. Проверяет валидность ID
4. Преобразует второй аргумент в строку
5. Вызывает `setInnerHTML`
6. Инвалидирует CSS-кэш

**Возвращаемое значение:**
- `C.JSValueRef` — `JSUndefined` (по стандарту DOM)

---

#### setOuterHTMLJS

**Поведение:**

2. Преобразует ID узла
3. Преобразует оба строковых аргумента
4. Вызывает `setAttribute`

6. Помечает состояние как "грязное"

#### getInnerHTMLJS

Получает HTML содержимое элемента.

**Параметры:**
- `args[0]` — ID элемента

**Поведение:**
1. Проверяет наличие аргумента

3. При отсутствии ID возвращает пустую строку
4. Вызывает `getInnerHTML`

**Возвращаемое значение:**
- `C.JSValueRef` — строка HTML (возвращается через `ctx.MakeString`)

---

#### getTextContentJS

Получает текстовое содержимое.

**Параметры:**
- `args[0]` — ID элемента

**Поведение:**
1. Проверяет наличие аргумента
2. Преобразует ID узла
3. При отсутствии ID возвращает пустую строку

**Возвращаемое значение:**

---

#### outerHTMLJS

Получает outerHTML элемента.

**Параметры:**
- `args[0]` — ID элемента

**Поведение:**
1. Проверяет наличие аргумента
2. Преобразует ID узла
3. При отсутствии ID возвращает пустую строку
4. Вызывает `outerHTMLString`
5. Выделяет память через `C.CString`
6. Освобождает память через `C.free` (defer)
7. Создаёт JS-строку через `C._makeString`

**Возвращаемое значение:**
- `C.JSValueRef` — строка outerHTML (JS-строка)

---

#### cloneNodeJS

Клонирует узел.

**Параметры:**
- `args[0]` — ID узла
- `args[1]` (опционально) — булево значение для глубокого клонирования

**Поведение:**
1. Проверяет наличие аргумента
2. Преобразует ID узла
3. При отсутствии ID возвращает null
4. По умолчанию `deep = false`
5. Если есть второй аргумент, преобразует его в boolean
6. Вызывает `cloneNode` с флагом глубины
7. При nil-узле возвращает null

**Возвращаемое значение:**
- `C.JSValueRef` — клонированный узел (JS-обёртка) или `JSNull`

---

#### containsJS

Проверяет, является ли узел потомком родителя.

**Параметры:**
- `args[0]` — ID родителя
- `args[1]` — ID потенциального потомка

**Поведение:**
1. Проверяет наличие 2 аргументов
2. Преобразует аргументы в ID
3. При невалидных ID возвращает false
4. Вызывает `contains`

**Возвращаемое значение:**
- `C.JSValueRef` — `JSBoolean` (true/false)

---

```go
import (
    "unsafe"

)
```

### css

Пакет CSS, используемый для:
- `InvalidateCache()` — инвалидация CSS-кэша после изменений DOM

## Управление памятью

Используется стандартный C-интерфейс для управления памятью:

- `C.CString(html)` — выделяет память для строки
- `C.free(unsafe.Pointer(cstr))` — освобождает память (через defer)
- `C._makeString(ctx.ctx, cstr)` — создаёт JS-строку из C-строки

---

## Обработка ошибок

### Стратегия возврата

Вместо паник или throw, все функции возвращают специальные JS-значения:

| Состояние | Возврат |
|-----------|---------|
| Недостаточно аргументов | `JSUndefined` |
| Невалидный узловой ID | `JSUndefined` или `JSNull` |
| Успешное выполнение | JS-значение результата |
| Ошибка получения строки | Возврат пустой строки или `JSUndefined` |

### Преобразование ошибок

- Ошибки преобразования JS-значений игнорируются (второе значение в `getArgString`)
- Невалидные ID узлов (< 0) интерпретируются как ошибки
- Внутренние ошибки Go не передаются наружу через JS-ошибки

---

## Инвалидация состояний

После изменений DOM вызываются следующие функции:

1. `css.InvalidateCache()` — инвалидация CSS-кэша (не всегда)
2. `SetDirty()` — пометка состояния как "грязное" (не всегда)

---

## Спецификации поведения

### Аргументы args

Все функции принимают слайс `C.JSValueRef` в качестве аргументов. Это позволяет передавать JS-значения из JavaScriptCore напрямую.

### Преобразование типов

- JS-строки преобразуются через `getArgString`
- JS-булевы значения преобразуются через `C.JSValueToBoolean`
- JS-числовые значения (для ID) проверяются на отрицательность

### Возвращаемые значения

- **Создающие функции** возвращают JS-обёртку созданного узла
- **Читающие функции** возвращают строки или булевы значения
- **Модифицирующие функции** возвращают `JSUndefined` или `JSNull` (согласно DOM-спецификации)

---

## Примеры использования

### Создание и настройка элемента

```javascript
const div = document.createElement("div");
div.innerHTML = "<span>Привет</span>";
div.setAttribute("id", "main");
```

В Go:
```go
elem := createElementJS(ctx, []C.JSValueRef{
    C._makeString(ctx.ctx, "div"),
})
```

### Удаление узла

```javascript
parent.removeChild(child);
```

В Go:
```go
result := removeChildJS(ctx, []C.JSValueRef{
    parentID,
    childID,
})
```

## Ограничения

### Не реализованные функции

- `querySelectorJS` — поиск элементов по селекторам
- `addEventListenerJS` — добавление обработчиков событий
- `dispatchEventJS` — диспатч событий
- `getElementsByClassNameJS` — поиск по классам

### Примечания

- Все операции DOM происходят асинхронно относительно CSS-рендеринга
- Инвалидация кэша происходит после каждой модификации
- Управление памятью JS-строк через C-интерфейс

---

## Безопасность

### Проверки валидации

1. Все функции проверяют количество аргументов перед выполнением
2. ID узлов проверяются на отрицательность
3. Преобразование ошибок игнорируется (предотвращение паник)

### Изоляция контекста

Каждая функция принимает `*Context`, обеспечивая изоляцию состояния исполнения.

---

## Тестирование

Для тестирования функции:

1. Создайте тестовый контекст
2. Запустите функцию с тестовыми аргументами
3. Проверьте возвращаемый `C.JSValueRef`
4. Инвалидируйте кэш после каждого теста

---

## Версионность

Файл следует архитектуре bridge layer и предназначен для использования с JavaScriptCore. Любые изменения в сигнатурах функций требуют обновления соответствующих объявлений в `bridge.c`.

## Примечание о вспомогательных функциях

Функции `jsToNodeID`, `getArgString`, `nodeToJS`, `createContext` объявлены в соседних пакетах и не находятся в этом файле. Структура `Context` и методы `MakeUndefined()`, `MakeNull()`, `MakeString()`, `MakeBoolean()` также определены в соседнем пакете.
