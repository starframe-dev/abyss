# Specification: domapi_embed.go

## Обзор

Файл `domapi_embed.go` содержит реализацию встроенного (embedded) JavaScript-кода DOM API для использования в Go-приложениях. Файл собирает несколько фрагментов JavaScript-кода, относящихся к различным аспектам DOM API, и объединяет их в единый IIFE (Immediately Invoked Function Expression).

## Публичный API

### Глобальные переменные

#### `domapiJSSource` (string)

Хранит собранную строку JavaScript-кода, которая представляет собой IIFE, содержащий все фрагменты DOM API.

- **Тип:** `string`
- **Инициализация:** Выполняется в функции `init()`
- **Назначение:** Предназначен для вставки в HTML или использования в качестве источника JavaScript-кода

#### `domapiFragments` ([]string)

Список названий тематических фрагментов DOM API в порядке загрузки.

- **Тип:** `[]string`
- **Элементы:**
  - `"style"` — фрагмент, связанный со стилями
  - `"element"` — фрагмент, связанный с элементами DOM
  - `"global"` — фрагмент, связанный с глобальными объектами
- **Назначение:** Определяет порядок подключения фрагментов. Фрагменты подключаются последовательно, сохраняя общую область видимости замыкания (shared closure scope).

### Функции

#### `init()` (func)

Инициализирует переменную `domapiJSSource`, считывая и объединяя фрагменты JavaScript.

**Поведение:**

1. Определяет директорию проекта относительно текущего файла источника
2. Для тестовых бинарных файлов использует относительный путь `internal/js/domapi`
3. Последовательно читает файлы JavaScript для каждого фрагмента из `domapiFragments`
4. Если файл не найден — вызывает `panic` с ошибкой
5. Объединяет содержимое файлов в единый IIFE

**Обработка ошибок:**

- Если файл не существует или не может быть прочитан — вызывается `panic` с сообщением о том, какой файл не удалось прочитать и какая ошибка возникла
- Не возвращает ошибок, так как инициализация ожидается всегда успешной

**Порядок загрузки фрагментов:**

- Фрагменты читаются в порядке, определённом в `domapiFragments`
- Каждый файл имеет формат `имя_fragmentа.js`
- Содержимое объединяется с разделением на символы новой строки

## Типы данных

### Фрагменты DOM API

Каждый элемент массива `domapiFragments` содержит строку с именем фрагмента:

- `"style"`: фрагмент, предоставляющий API для работы со стилями (CSS, style properties и т.д.)
- `"element"`: фрагмент, предоставляющий API для работы с элементами DOM (создание, манипуляция, события)
- `"global"`: фрагмент, предоставляющий API для работы с глобальными объектами (window, document, navigator и т.д.)

## Реализационные детали

### Структура IIFE

Собранная строка `domapiJSSource` имеет структуру:

```javascript
(function() {
    // содержимое всех фрагментов
})()
```

- Это IIFE (Immediately Invoked Function Expression)
- Все фрагменты находятся в одной области видимости
- Переменные и функции фрагментов не утекают в глобальный scope браузера
- Фрагменты загружаются в определённом порядке для корректной зависимости

### Определение директории

Функция использует `runtime.Caller(0)` для определения пути к текущему файлу:

- Для обычных бинарных файлов — путь к директории источника
- Для тестовых бинарных файлов — используется fallback к `internal/js/domapi`

### Чтение файлов

Каждый фрагмент читается через `os.ReadFile()`:

- Файл существует: содержимое добавляется в `parts`
- Файл не существует: вызывается `panic`

### Объединение фрагментов

После успешного чтения всех файлов:

- Все содержимое из `parts` объединяется через `strings.Join(parts, "\n")`
- Добавляются открывающие и закрывающие скобки IIFE
- Результат сохраняется в `domapiJSSource`

## Ограничения и предположения

### Предположения о среде выполнения

- Файл предназначен для использования в Go
- JavaScript файлы должны существовать в директории `domapi`
- Инициализация должна выполняться только один раз (автоматически при загрузке пакета)

### Ограничения обработки ошибок

- Ошибки чтения файлов обрабатываются через `panic`, а не возвращаются как ошибки
- Это означает, что инициализация должна всегда удаваться в production-среде
- Для тестовых сценариев предусмотрен fallback к относительному пути

### Порядок загрузки

- Фрагменты должны загружаться в порядке, заданном в `domapiFragments`
- Фрагменты зависят друг от друга (последние могут использовать переменные из предыдущих)
- Общий scope замыкания позволяет использовать переменные между фрагментами

## Тестирование

### Рекомендации по тестированию

- Проверить, что файл инициализируется успешно при наличии всех фрагментов
- Проверить обработку ошибки при отсутствии одного из фрагментов
- Проверить корректность чтения всех файлов
- Проверить порядок объединения фрагментов

### Тестовые сценарии

1. Убедиться, что `domapiJSSource` содержит объединённый код всех фрагментов
2. Убедиться, что порядок фрагментов соответствует `domapiFragments`
3. Проверить обработку ошибки чтения файла (хотя и приводит к panic)

## Безопасность

- Файлы JavaScript читаются из директории `domapi`
- В production-среде предполагается, что файлы безопасны
- Для тестов используется относительный путь, что может потребовать проверки безопасности

## Изменения в будущем

- Расширение списка фрагментов в `domapiFragments`
- Добавление новых фрагментов JavaScript
- Изменение порядка загрузки при необходимости
