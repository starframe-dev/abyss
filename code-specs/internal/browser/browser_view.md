# Specification: browser_view.go

## Обзор

Файл `browser_view.go` реализует метод `View()` для типа `Model`, который является частью интерфейса `tea.Model` из библиотеки TUI (Terminal User Interface). Метод отвечает за рендеринг текстового представления браузера в терминале с использованием библиотеки `lipgloss` для стилизации.

## Публичный API

### Функция `View() string`

Метод `View()` на типе `Model` возвращает строку, представляющую визуальное состояние браузера.

#### Входные параметры
- `m Model` — состояние модели браузера, включающее:
  - `m.Tabs` — срез табов браузера
  - `m.ActiveTab` — индекс активного таба
  - `m.Mode` — режим отображения: `ModeLoading`, `ModeError`, `ModeView`, `ModeAddress`
  - `m.Address` — адресная строка с методом `View()` и `Value()`
  - `m.Err()` — метод для получения ошибки (если режим `ModeError`)
  - `m.Width` — ширина терминала
  - `m.Height` — высота терминала
  - `m.Viewport` — смещение и размер области просмотра
  - `m.ANSILines()` — метод возврата буфера вывода
  - `m.ZoomFactor()` — метод получения фактора масштабирования
  - `m.OffsetX()` — метод получения горизонтального смещения

#### Выход
- `string` — отформатированная строка с визуальным представлением браузера

### Вспомогательная функция `center(text string, width int) string`

Центрирует текст по горизонтали в пределах заданной ширины.

#### Входные параметры
- `text string` — текст для центрирования
- `width int` — целевая ширина

#### Выход
- `string` — отцентрированный текст

## Типы и состояние

### Модель `Model`

Структура модели браузера (полное определение недоступно в данном файле):

- `Tabs []Tab` — массив табов
- `ActiveTab int` — индекс активного таба
- `Mode Mode` — текущий режим отображения
- `Address` — адресная строка
- `Width int` — ширина терминала
- `Height int` — высота терминала
- `Viewport` — информация о смещении области просмотра
- `Err()` — метод получения ошибки
- `ZoomFactor()` — метод получения фактора масштабирования
- `OffsetX()` — метод получения горизонтального смещения
- `ANSILines()` — метод получения буфера вывода

### Режимы отображения (`Mode`)

1. `ModeLoading` — режим загрузки
2. `ModeError` — режим отображения ошибки
3. `ModeView` — режим отображения контента
4. `ModeAddress` — режим отображения адресной строки

## Логика работы

### Таб-бар

1. Стиль неактивного таба:
   - Внутренние отступы: 0 слева/справа, 1 сверху/снизу
   - Фон: `#313244`
   - Текст: `#cdd6f4`

2. Стиль активного таба:
   - Внутренние отступы: 0 слева/справа, 1 сверху/снизу
   - Фон: `#45475a`
   - Текст: `#f5c2e7`
   - Жирное начертание

3. Для каждого таба:
   - Если `URL` пуст — отображается "New Tab"
   - Иначе URL обрезается от протокола (`https://`, `http://`)
   - Если длина после обрезки > 20 символов — обрезается до 20 + "…"

### Хедер-бар

1. Стиль:
   - Фон: `#1e1e2e`
   - Текст: `#cdd6f4`
   - Отступы: 0 слева/справа, 1 сверху/снизу

2. Режим `ModeAddress`:
   - Отображается "Abyss " + `m.Address.View()`

3. Режим `ModeView`:
   - Отображается `m.Address.Value()`
   - Если адрес пуст — "Abyss"
   - Если масштаб отличается от 1.0 — добавляется `[%.0f%%]` с масштабом

### Область контента

В зависимости от режима (`m.Mode`):

#### `ModeLoading`

Отображается текст "Loading..." в центре экрана с помощью функции `center()`.

#### `ModeError`

Отображается:
1. "Error: " + значение ошибки из `m.Err()`
2. Подсказка: "Press Ctrl+L to edit URL or Q to quit"

#### `ModeView`

1. Получение строк из `m.ANSILines()`
2. Вычисление видимой области:
   - Смещение по Y: `m.Viewport.YOffset`
   - Высота: `m.Viewport.Height` (минимум 24 линии)
   - Если смещение >= количества строк — корректируется
   - Если конец > количества строк — обрезается
3. Применяется горизонтальная прокрутка:
   - Ширина: `m.Width` (минимум 80)
   - Смещение X: `m.OffsetX()`
   - Быстрый путь: при `OffsetX == 0` и видимой ширине строки ≤ `m.Width` строка отдаётся без изменений
   - Иначе строка обрезается **ANSI-осознанно** через `clipANSI(line, offsetX, w)` — считаются только печатные колонки, а SGR-последовательности переносятся целиком
4. Обрезка выполняется в **новый срез**, а не в `visible` на месте: `visible` делит backing array с `tab.ANSILines`, и запись на месте необратимо портила исходные строки

### Почему нельзя резать ANSI как текст

Строка с ASCII-картинкой стоит ~1300 рун на 64 видимые колонки (по ~20 рун на ячейку из-за `\x1b[38;2;r;g;b;48;2;r;g;bm`). Прямой `[]rune(line)[start:end]`:

- обрывал строку после ~6 колонок вместо `m.Width`;
- оставлял висячий `\x1b` или недобитую CSI-последовательность, которую терминал/cue-tty трактовал как erase-to-end-of-line — остаток картинки пропадал.

Реализация — `ansi_clip.go`: `splitANSI` (разбор на сегменты с активным стилем), `visibleWidth` (счёт печатных колонок), `clipANSI` (окно по колонкам с переносом SGR).

#### `ModeAddress`

Отображается адресная строка, центрированная в области контента.

| Активный таб | `#45475a` |
| Текст табов | `#cdd6f4` |

| Текст хедера | `#cdd6f4` |

## Важные заметки

1. Все строки с URL обрабатываются без протокола при отображении
2. Горизонтальная прокрутка реализуется через ANSI-осознанную обрезку (`clipANSI`), см. «Почему нельзя резать ANSI как текст»
3. Вертикальная прокрутка реализована через смещение области просмотра
4. Библиотека `lipgloss` используется для стилизации текста
5. Требуется поддержка ANSI-кодов в терминале для корректного отображения цветов
6. Библиотека cue-tty подразумевается для совместимости
7. Режим `ModeAddress` отображает адресную строку в центре области контента
8. Режим `ModeLoading` отображает "Loading..." в центре экрана
9. Режим `ModeError` отображает сообщение об ошибке и подсказку для выхода
