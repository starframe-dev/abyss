# Спецификация `internal/browser/ansi_clip.go`

## Назначение

Файл реализует внутреннюю обработку строк с ANSI-последовательностями: безопасное выделение поддерживаемых цветов, подсчет видимой ширины и обрезку по экранным колонкам. Пакет — `browser`; все объявленные здесь функции и типы непубличные и доступны только внутри пакета.

## Типы и функции

### `ansiSegment`

Внутренний сегмент текста с неизменным для сегмента стилем:
- `style []string` — последовательности SGR, задающие поддерживаемые цвета;
- `text string` — отображаемый текст сегмента.

### `splitANSI(s string) []ansiSegment`

Разбирает строку на сегменты. Сохраняет только SGR-последовательности с 24-битным foreground/background цветом, пригодные для renderer; остальные escape-последовательности и терминальные управляющие символы удаляет.

Сначала удаляет сырые байтовые C1-последовательности вместе с payload, затем заменяет некорректный UTF-8 на пустую строку. ESC `[` рассматривается как CSI: параметры читаются до финального символа в диапазоне `0x40–0x7e`; только завершающий `m` с допустимыми параметрами влияет на стиль. Пустые параметры и `0` сбрасывают стиль; допустимые цветовые SGR накапливаются. ESC `]` (OSC) пропускается до BEL, ST (`0x9c`) или ESC `\`. ESC `P`, `X`, `^`, `_` пропускаются до ST. Прочие ESC-последовательности отбрасываются. Unicode C1 CSI и строковые управляющие последовательности также пропускаются. Управляющие Unicode-символы и форматирующие `Cf` удаляются, кроме ZWNJ и ZWJ. Обычные символы собираются в сегменты; пустые сегменты не выдаются. Каждый сегмент получает копию текущего списка стилей.

### `stripRawC1Controls(s string) string`

Внутренняя предварительная обработка байтов. Декодирует UTF-8 по рунам; при некорректном байте распознает сырые C1-коды: CSI (`0x9b`) удаляется до финального байта, а DCS/SOS/OSC/PM/APC (`0x90`, `0x98`, `0x9d`, `0x9e`, `0x9f`) — до ST или ESC `\`; для OSC также учитывается BEL. Остальные некорректные байты пропускаются. Валидные UTF-8-последовательности сохраняются без изменений.

### `validRendererSGR(params string) bool`

Проверяет параметры SGR. Допускаются пустая строка и `0`, либо одна или несколько групп, разделенных точкой с запятой, каждая строго вида `38;2;R;G;B` или `48;2;R;G;B`. Каждый компонент RGB должен быть десятичным целым от 0 до 255. Любые иные коды, неполные группы или некорректные значения означают `false`.

### `visibleWidth(line string) int`

Разбирает строку через `splitANSI` и суммирует ширину текста сегментов в терминальных колонках посредством `runewidth.StringWidth`. ANSI-коды и отфильтрованные управляющие символы ширину не добавляют.

### `clipANSI(line string, start, width int) string`

Возвращает фрагмент строки, соответствующий диапазону колонок `[start, start+width)`, сохраняя допустимые цвета. При `width <= 0` возвращает пустую строку; отрицательный `start` приравнивается к нулю.

Текст каждого сегмента обходится по графемным кластерам (`uniseg`), а координаты считаются в экранных колонках. Полностью попавший в диапазон кластер сохраняется. Если граница диапазона пересекает кластер шириной больше одного столбца, пересекающаяся часть заменяется пробелами, чтобы сохранить геометрию колонок. Кластеры нулевой ширины добавляются только вслед за включенным целиком кластером. Для непустой выбранной части сегмента перед текстом выводятся его SGR-стили, а после — `ESC[0m`, чтобы стиль не утекал за фрагмент. Обработка прекращается при достижении конца диапазона.

## Зависимости и ограничения

Используются `strconv`, `strings`, `unicode`, `unicode/utf8`, а также `github.com/mattn/go-runewidth` и `github.com/rivo/uniseg`. Функции не выполняют ввод-вывод и не меняют внешнее состояние. Поддерживаемый набор ANSI-цветов намеренно ограничен 24-битными foreground/background SGR; другие стили не сохраняются.
