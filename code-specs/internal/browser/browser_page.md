# Спецификация модуля `browser_page.go`

## Обзор

Модуль пакета `browser` загружает страницы, управляет JavaScript-контекстами по вкладкам, загружает внешние CSS и изображения, вычисляет стили и макет, а также рендерит результат в ASCII/ANSI.

## Константы и состояние

- Data URL изображения ограничен 16 МиБ; кэш изображений — 64 МиБ с оценкой памяти 8 байт на пиксель; внешних изображений обрабатывается не более 64 и их совокупный бюджет загрузки — 64 МиБ.
- Кэш изображений индексирован источником, имеет порядок вытеснения FIFO и защищён RWMutex. `render.ImageProvider` при инициализации назначается функции `cachedImage`.
- Состояние JS защищено mutex: один активный runtime переключается между вкладками, остальные сохраняются в карте по ID. Есть функции закрытия всех контекстов и контекста конкретной вкладки.

## Загрузка и рендеринг

`loadPage(url, viewportWidth)` запускает `loadPageContext` с фоновым контекстом. `loadTabPage(ctx, url, viewportWidth, tabID, requestID)` оборачивает команду загрузки и добавляет идентификаторы вкладки/запроса к сообщениям `PageLoadedMsg` и `PageErrorMsg`. Основная реализация — `loadPageForTab`.

Порядок работы: загрузка HTML через `fetcher.FetchContext`; проверка отмены; `dom.Parse`; под mutex создаётся JS-контекст, инициализируется DOM, регистрируются bridge-функции, система событий и DOM API. В URL для JavaScript экранируются обратная косая черта, одинарная кавычка и перевод строки. Выполняются скрипты (их ошибка игнорируется), отправляется событие `DOMContentLoaded`, получается финальный DOM и сохраняется runtime вкладки. Затем загружаются внешние CSS и изображения, вычисляются стили через `css.ComputeWithExternalAtWidth`, строится layout, его боксы и стили устанавливаются в JS-контекст, выполняется рендеринг и формируются ASCII- и ANSI-строки. Отмена контекста возвращается как ошибка; ошибки bridge и DOM API возвращаются с префиксами `js bridge init:` и `js dom api error:`.

Загрузка учитывает отмену на основных этапах. При ошибке fetch, отмене, ошибках инициализации JS возвращается `PageErrorMsg`; успешная загрузка возвращает `PageLoadedMsg` с URL и внешними CSS. При заданном `ABYSS_DUMP_ANSI` ANSI-строки дополнительно записываются в файл, ошибки записи игнорируются.

`reRenderCmd(viewportWidth, zoomFactor, tabID, requestID, pageURL, externalCSS)` активирует runtime вкладки. Если runtime, контекст или DOM недоступны либо URL не совпадает, возвращает nil. Иначе отмечает JS чистым, масштабирует ширину (минимум 10), пересчитывает CSS с внешними стилями, layout и рендеринг и возвращает `PageRenderedMsg` с ID вкладки/запроса. Runtime сохраняется после операции.

## Внешние ресурсы

### CSS

`fetchExternalCSS` использует фоновый контекст; `fetchExternalCSSContext` принимает контекст и находит ссылки через `FindLinkStylesheets`. Обрабатывает до 64 уникальных пар URL и media; media длиннее 256 байт пропускается. URL разрешается относительно страницы. До четырёх worker-процессов параллельно вызывают `fetcher.FetchCSS`; ошибки пропускаются. CSS оборачивается в `@media`, если атрибут media непустой. Добавляемый контент ограничен общим бюджетом 4 МиБ; порядок результата соответствует порядку ссылок. Пустой результат возвращается как nil/пустой слайс.

### Изображения

`fetchImages` использует фоновый контекст; `fetchImagesContext` принимает контекст. Data URL не загружаются сетью. Для внешних изображений относительные URL разрешаются и атрибут `src` заменяется абсолютным адресом. Повторяющиеся URL дедуплицируются; уже кэшированные не запрашиваются. Не более 64 источников, одновременно работают максимум два worker-процесса. Результаты учитываются в порядке исходных URL, общий бюджет тела — 64 МиБ; только успешно декодированные изображения, укладывающиеся в бюджет, сохраняются в кэше. Ошибки загрузки и декодирования не прерывают обработку.

`decodeDataImage` принимает только `data:` с base64, ограничивает размер URL и декодирует через `asciirender.Decode`. Кэш игнорирует изображения с некорректными/чрезмерными размерами и вытесняет старые записи при превышении бюджета.

## URL

`ResolveURL(base, rel)` парсит оба URL и применяет `ResolveReference`; при ошибке разбора base возвращает `rel`, при ошибке разбора rel — пустую строку. `ResolveURLForTest` и `FetchExternalCSSForTest` — тестовые обёртки.

## JS-таймеры

`processJSTimers(tabID, expectedURL)` активирует runtime вкладки, выполняет таймеры только при совпадении URL, возвращает признак dirty и сохраняет runtime. При недоступном runtime возвращает false.

## Зависимости

Используются Bubble Tea и внутренние пакеты `ascii`, `asciirender`, `cellmetrics`, `css`, `dom`, `fetcher`, `js`, `layout`, `render`, а также стандартные `context`, `encoding/base64`, `errors`, `fmt`, `image`, `net/url`, `os`, `strings`, `sync`.
