# Спецификация пакета `renderer`

## Обзор

Пакет `renderer` является **устаревшим (deprecated)** и не должен использоваться в новых кодобазе. Для всех задач рендеринга следует использовать пакет `internal/render`.

## Текущее состояние

- **Статус**: Устарел (deprecated)
- **Пакет**: `internal/renderer`
- **Импортировать**: ❌ Запрещено
- **Использовать**: ❌ Запрещено

## Рекомендация

Все существующие и новые кодобазные модули должны импортировать и использовать пакет `internal/render` вместо устаревшего `renderer`.

## Публичный API

Пакет не содержит публичных функций, типов или констант. Файл содержит только директиву устаревания:

```go
// Package renderer is deprecated. Use internal/render instead.
package renderer
```

## Типы

- Публичных типов нет.

## Функции

- Публичных функций нет.

## Структура

```
internal/renderer/
└── renderer.go (устаревший файл)
```

## Примеры использования

### ❌ НЕПРАВИЛЬНО (устаревший способ)

```go
import "internal/renderer"  // ❌ Устаревший импорт
```

### ✅ ПРАВИЛЬНО (современный способ)

```go
import "internal/render"  // ✅ Актуальный импорт
```

## Зависимости

- **Прямые зависимости**: Нет
- **Обратные зависимости**: Возможны модули, использующие устаревший пакет (требуется рефакторинг)

## Примечания

1. Миграция: Все импорты `internal/renderer` необходимо заменить на `internal/render`
2. Тесты: Если существуют тесты для устаревшего пакета, их следует либо обновить, либо удалить
3. Документация: Любые ссылки на `renderer` в документации требуют обновления
