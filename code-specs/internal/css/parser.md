# Спецификация CSS-парсера

## Обзор

Пакет `css` в `internal/css/parser.go` содержит функции для разбора inline-стилей и таблиц стилей, а также упрощённого подсчёта специфичности селектора.

## Типы

### `Declaration`
Поля:
- `Property string` — имя свойства после удаления пробелов по краям.
- `Value string` — значение после удаления пробелов по краям и завершающего `!important`, если он распознан.
- `Important bool` — признак наличия завершающего `!important` без учёта регистра.

### `Rule`
Поля:
- `Selectors []string` — селекторы правила, разделённые запятыми и обрезанные по краям.
- `Declarations []Declaration` — декларации правила.
- `MediaQuery string` — накопленные условия `@media`.
- `SupportsQuery string` — накопленные условия `@supports`.

## Публичные функции

### `ParseInline(style string) []Declaration`
Разбивает вход по `;` вне круглых скобок, пропускает пустые части и части без `:`. Первое двоеточие разделяет свойство и значение. Пробелы по краям свойства и значения обрезаются; завершающее `!important` распознаётся без учёта регистра, удаляется из значения, а `Important` устанавливается в `true`. Функция не возвращает ошибок.

### `ParseStyleSheet(css string) []Rule`
Сначала удаляет комментарии `/* ... */`, затем разбирает правила. Обычный prelude до `{` трактуется как список селекторов, разделённых запятыми. Декларации внутри блока разбираются теми же правилами, что и inline-декларации. Незакрытый блок прекращает разбор оставшегося текста.

Поддерживаются вложенные `@media` и `@supports`: условия одного типа соединяются через ` and `, а соответствующие поля включаются в создаваемые правила. Другие at-rule пропускаются вместе с содержимым. Глубина рекурсии at-rule ограничена константой 32; при достижении лимита вложенный вызов возвращает `nil`.

Закрывающая скобка блока ищется с учётом вложенных фигурных скобок, строк в одинарных/двойных кавычках, экранирования обратной косой чертой и круглых скобок. Комментарии при удалении не учитывают кавычки; незакрытый комментарий удаляет оставшуюся часть строки.

### `Specificity(selector string) int`
Рассчитывает упрощённое числовое значение `a*100 + b*10 + c`. Селектор токенизируется по пробелам и комбинаторам `>`, `+`, `~`, кроме разделителей внутри квадратных скобок. Для токенов учитываются все символы `#` как `a`, все `.` как `b`, `[` как `b`, а `:` — как `b`, кроме двойного `::`, которое учитывается как `c`.

Для подсчёта `c` токен дополнительно разделяется по `.` и `#`; подходящие части, не начинающиеся с `#`, `.`, `[` или `:`, проверяются как тип-селекторы. Тип-селектор допускает только буквы Unicode, дефис и подчёркивание. Это упрощённая эвристика, а не полная реализация правил специфичности CSS; в частности, символы внутри некоторых синтаксических конструкций могут учитываться буквально.

## Внутренние функции

- `stripComments` удаляет участки от `/*` до следующего `*/`; если завершения нет, удаляет до конца строки.
- `findClosingBrace` возвращает индекс соответствующей `}` либо `-1`, если её нет.
- `parseDeclarations` разбивает блок по `;` вне круглых скобок, пропускает пустые части и части без двоеточия, затем использует первое `:`.
- `splitBySemicolon` учитывает глубину круглых скобок; кавычки не учитываются.
- `tokenizeSelector` сохраняет содержимое квадратных скобок в токене и разделяет по комбинаторам и пробелам.
- `splitByClassID` начинает новую часть на каждом `.` или `#`.
- `isValidTypeSelector` проверяет непустую строку на допустимые Unicode-буквы, `-` и `_`.

Парсер возвращает частичные или пустые результаты вместо ошибок. Он не проверяет допустимость CSS-свойств и не реализует полный синтаксис CSS.
