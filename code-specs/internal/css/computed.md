# Спецификация вычисленных стилей

## Назначение

`internal/css/computed.go` вычисляет стили для узлов DOM, применяя правила CSS, каскад и обработку значений. Правила берутся из элементов `<style>` и переданных внешних CSS-строк.

## Публичный API

- `Compute(doc *dom.Node) map[*dom.Node]ComputedStyle` вычисляет стили с шириной viewport 0.
- `ComputeAtWidth(doc *dom.Node, viewportWidth float64) map[*dom.Node]ComputedStyle` вычисляет стили для указанной ширины viewport в CSS-пикселях.
- `ComputeWithExternal(doc *dom.Node, externalCSS []string) map[*dom.Node]ComputedStyle` вычисляет стили с внешними CSS и шириной viewport 0.
- `ComputeWithExternalAtWidth(doc *dom.Node, externalCSS []string, viewportWidth float64) map[*dom.Node]ComputedStyle` вычисляет стили с внешними CSS и указанной шириной viewport.
- `InvalidateCache()` очищает поля документа и стилей глобального кэша; её следует вызывать при изменении DOM через JS.

## Сбор правил и кэш

Стили из `<style>`-элементов извлекаются через `FindStyleTags()` и разбираются `ParseStyleSheet`. Если у элемента задан непустой атрибут `media`, его содержимое оборачивается в `@media ... { ... }` перед разбором. Затем к правилам добавляются правила из каждой внешней CSS-строки.

Глобальный кэш защищён `sync.Mutex` и хранит указатель на документ, карту стилей и ширину viewport. Кэш возвращается только при совпадении документа и ширины, наличии сохранённой карты и пустом списке внешнего CSS. Результат каждого вычисления сохраняется в кэше; внешние CSS при последующих вызовах не являются условием попадания в кэш. Инвалидация обнуляет указатель документа и карту стилей.

## Вычисление и каскад

Узлы обходятся рекурсивно, начиная с переданного документа. Для каждого узла создаётся стиль `Default()`. От родителя наследуется только `Color`. Пользовательские CSS-свойства наследуются отдельно: карта переменных копируется от родителя.

Для каждого правила проверяются media- и supports-условия и каждый селектор. Подходящие декларации собираются с их специфичностью; декларации атрибута `style` добавляются как inline. Стабильная сортировка применяет декларации от низшего приоритета к высшему: сначала обычные перед `!important`, затем не-inline перед inline, затем по возрастанию специфичности. При равном приоритете сохраняется исходный порядок.

Сначала все подходящие пользовательские свойства записываются в карту переменных (имена нормализуются к нижнему регистру), затем обычные свойства применяются после разрешения `var()`. Разрешение поддерживает fallback через запятую, вложенные вызовы и обнаружение циклов; глубина ограничена 64. Некорректная или неразрешимая подстановка без пригодного fallback даёт пустое значение.

После вычисления текущего узла обработка рекурсивно выполняется для его детей. `nodeMatchesSelector` отклоняет nil и не-элементы, обрабатывает `:root`, пустой селектор и в остальных случаях делегирует проверку `node.Matches`.

## Media и supports

Условия длиннее 256 символов не совпадают. Пустое условие совпадает. Media-проверка поддерживает списки альтернатив через запятую, `all`, `screen`, `only`, конструкции `screen and`/`all and`, а также ограничения `min-width` и `max-width` в `px`; `print`, `not` и неподдерживаемые формы не совпадают. Supports-проверка поддерживает `or`, `and`, `not`, скобки и декларации `display` со значениями block, inline, flex, grid, none, а также `position` со значениями static, relative, absolute.

## Применение свойств

`applyDeclaration` распределяет свойства по обработчикам:

| Категория | Свойства |
|---|---|
| Box model | `margin`, `margin-*`, `padding`, `padding-*` |
| Border | `border`, `border-*` |
| Размеры | `width`, `height`, `min-width`, `max-width`, `gap`, `grid-template-columns`, `grid-template-rows` |
| Смещения | `top`, `left`, `right`, `bottom` |
| Цвет | `color`, `background-color` |
| Layout | остальные свойства |

Специализированные обработчики разбирают соответствующие поля `ComputedStyle`. Layout-обработчик поддерживает `display`, `position`, `overflow`, `z-index`, `text-align`, `flex-direction`, `justify-content`, `align-items`, `flex-wrap`, `order`, `flex-grow` и `flex-shrink`. Для grow/shrink результат ограничивается снизу нулём.

## Ограничения

Фактическая поддержка селекторов определяется `dom.Node.Matches`; этот модуль сам не разбирает комбинации селекторов. Условия media/supports и подстановки CSS-переменных реализованы ограниченными наборами форм, описанными выше. Обрабатываются только перечисленные свойства; остальные декларации не меняют вычисленный стиль.
