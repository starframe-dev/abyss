# Computed Style Specification

## Описание

Модуль `css/computed.go` отвечает за вычисление вычисленных стилей для всех узлов DOM-документа. Реализует каскад CSS, обработку специфичности и парсинг значений CSS.

## Публичный API

### Функции

#### `Compute(doc *dom.Node) map[*dom.Node]ComputedStyle`

Вычисляет стили для всех узлов документа.

**Параметры:**
- `doc`: корневой узел DOM документа

**Возвращает:**
- Карта, где ключ — узел, значение — вычисленные стили для этого узла

**Поведение:**
- Использует глобальный кэш для оптимизации многократных вызовов
- Возвращает закэшированные стили, если документ не изменился и нет внешних CSS

#### `ComputeWithExternal(doc *dom.Node, externalCSS []string) map[*dom.Node]ComputedStyle`

Вычисляет стили с учётом дополнительных внешних CSS-строк.

**Параметры:**
- `doc`: корневой узел DOM документа
- `externalCSS`: слайс с внешними CSS-строками

**Возвращает:**
- Карта узлов к вычисленным стилям

**Поведение:**
- Парсит `<style>` теги внутри документа
- Добавляет правила из внешних CSS-строк
- Вычисляет стили для всех узлов
- Кэширует результат только если внешние CSS пусты

#### `InvalidateCache()`

Очищает кэш вычисленных стилей.

**Поведение:**
- Устанавливает `cached.doc = nil`
- Устанавливает `cached.styles = nil`
- Должна вызываться при модификации DOM через JS

## Типы

### Глобальный кэш

```go
var cached struct {
    sync.Mutex
    doc    *dom.Node
    styles map[*dom.Node]ComputedStyle
}
```

Глобальная переменная для хранения закэшированных вычисленных стилей. Защищена `sync.Mutex` для конкурентного доступа.

## Алгоритм вычисления

### 1. Сбор правил CSS

Правила собираются из двух источников:

1. **Встроенные CSS:** парсинг `<style>` тегов в документе через `doc.FindStyleTags()`
2. **Внешний CSS:** парсинг предоставленных внешних строк через `ParseStyleSheet()`

Все правила объединяются в один слайс `[]Rule`.

### 2. Рекурсивное вычисление узлов

Функция `computeNode` обрабатывает каждый узел рекурсивно:

```
документ → все узлы → все дети → ...
```

### 3. Соотношение с селекторами

Для каждого узла проверяются все селекторы правил:

```
для каждого правила:
  для каждого селектора:
    если узел соответствует селектору:
      добавить правило к списку соответствий
```

### 4. Сортировка по специфичности

Списки соответствий сортируются по специфичности (от меньшей к большей), чтобы стили с большей специфичностью перекрывали стили с меньшей.

```
сортировка:
  для i от 0 до len(matches)-1:
    для j от i+1 до len(matches):
      если matches[i].specificity > matches[j].specificity:
        поменять местами
```

### 5. Применение стилей

Для каждого соответствия применяются декларации. Затем применяются инлайн стили из атрибута `style`.

### 6. Рекурсия к детям

После обработки текущего узла вызывается рекурсия для всех детей.

## Парсинг селекторов

Функция `nodeMatchesSelector` обрабатывает простые селекторы:

### Поддерживаемые комбинации:

1. **Прямые потомки** (`>`)
2. **Десцendanт** (пробел)
3. **Соседи** (`+`, `~`)
4. **Простые селекторы**

### Логика:

1. Если селектор содержит `>`:
   - Проверяет родителя по первому селектору
   - Проверяет сам узел по второму селектору
2. Если один токен:
   - Проверяет соответствие
3. Если несколько токенов:
   - Игнорирует комбинационные селекторы (`>`, `+`, `~`)
   - Проверяет соответствие последнему токено

## Применение деклараций

Функция `applyDeclaration` распределяет декларации по категориям:

### Категории свойств:

| Категория | Свойства |
|-----------|----------|
| Box Model | `margin`, `margin-`, `padding`, `padding-` |
| Border | `border`, `border-` |
| Dimensions | `width`, `height`, `min-width`, `max-width`, `gap`, `grid-template-columns`, `grid-template-rows` |
| Offset | `top`, `left`, `right`, `bottom` |
| Color | `color`, `background-color` |
| Layout | все остальные |

### Специфичные обработчики:

- `applyBoxModel` — margin/padding
- `applyBorder` — border
- `applyDimensions` — ширина/высота
- `applyOffset` — позиционирование
- `applyColor` — цвета
- `applyLayout` — layout свойства

## Структура вычисленных стилей

Тип `ComputedStyle` содержит поля для всех CSS свойств, которые могут быть установлены через этот модуль:

- `Margin` — box margin
- `Padding` — box padding
- `BorderTop/Bottom/Left/Right` — border для каждой стороны
- `BorderRadiusTopLeft/TopRight/BottomRight/BottomLeft` — border-radius для углов
- `Width/Height/MinWidth/MaxWidth` — размеры
- `Gap` — gap между элементами
- `GridTemplateColumns/Rows` — grid-шаблон
- `Top/Left/Right/Bottom` — offset позиционирования
- `Color/BackgroundColor` — цвета
- `Display/Position/Overflow/ZIndex` — layout
- `FlexDirection/JustifyContent/AlignItems` — flexbox
- `FlexGrow/FlexShrink` — flex свойства

## Кэширование

### Условия использования кэша:

Кэш используется, когда:
1. Документ тот же (`cached.doc == doc`)
2. Есть закэшированные стили (`cached.styles != nil`)
3. Нет внешних CSS (`len(externalCSS) == 0`)

### Очистка кэша:

`InvalidateCache()` очищает кэш при модификации DOM, чтобы избежать использования устаревших данных.

## Производительность

- Глобальный кэш уменьшает вычислительные затраты на повторные вызовы
- Рекурсивная обработка узлов позволяет обрабатывать вложенные структуры
- Парсинг происходит только один раз при первом вызове для документа

## Ограничения

- Селекторы обрабатываются только для простых комбинаций
- Поддерживаются только прямые потомки и десцendanты
- Сложные селекторы (`:nth-child`, псевдоклассы) не поддерживаются
