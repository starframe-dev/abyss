# Selector Nth Specification

## Описание

Модуль реализует логику селектора `:nth-child` и связанных селекторов CSS (`:nth-of-type`) для работы с DOM-деревом в пакете `abyss`.

## Публичный API

### Типы

#### `Node`
Классическая структура узла DOM с полями `Parent`, `Children`, `Type`, `TagName`.

#### `ElementNode`
Тип узла элемента (не комментария, не текстового узла).

### Функции

#### `childIndex(n *Node, ofType bool) int`

**Назначение:** Возвращает 1-индексированный индекс узла `n` среди элементарных детей его родителя.

**Параметры:**
- `n *Node` — узел для поиска
- `ofType bool` — если `true`, учитываются только дети с одинаковым тегом

**Возвращаемое значение:**
- Индекс 1-based (начинается с 1)
- `0` если узел не найден, у узла нет родителя, или родитель не содержит элементов

**Поведение:**
- Если `n` или `n.Parent` nil — возвращает `0`
- Пропускает не-элементные узлы (текстовые узлы, комментарии)
- При `ofType=true` учитывает только узлы с одинаковым `TagName` (case-insensitive)
- При `ofType=false` считает все элементарные узлы

#### `lastChildIndex(n *Node, ofType bool) int`

**Назначение:** Возвращает 1-индексированный индекс узла `n` обратный (начинается с последнего элемента).

**Параметры:**
- `n *Node` — узел для поиска
- `ofType bool` — если `true`, учитываются только дети с одинаковым тегом

**Возвращаемое значение:**
- Индекс обратный (считается от конца: последний элемент — 1)
- `0` если узел не найден, у узла нет родителя, или родитель не содержит элементов

**Поведение:**
- Если `n` или `n.Parent` nil — возвращает `0`
- Пропускает не-элементные узлы
- При `ofType=true` учитывает только узлы с одинаковым `TagName`
- При `ofType=false` считает все элементарные узлы

#### `matchNth(arg string, idx int) bool`

**Назначение:** Проверяет, соответствует ли индекс `idx` селектору `:nth-child(arg)`.

**Параметры:**
- `arg string` — строка селектора (например, "even", "odd", "2n+1", "3n", "-n+3", "n", "0", или число)
- `idx int` — индекс узла для проверки

**Возвращаемое значение:**
- `true` — индекс соответствует селектору
- `false` — индекс не соответствует или селектор не валиден

**Поддерживаемые формы:**
- `"even"` — чётные индексы (0, 2, 4, 6, ...)
- `"odd"` — нечётные индексы (1, 3, 5, ...)
- `"2n+1"` — индексы вида 2k+1
- `"3n"` — кратные 3
- `"-n+3"` — индексы 1, 2, 3
- `"n"` — все индексы
- `"0"` — только первый элемент (индекс 0)
- Любое число — только этот индекс

**Поведение:**
- Убирает пробелы из аргумента
- Приводит к нижнему регистру
- Если строка пуста — возвращает `false`
- Если строка содержит только число — сравнивает напрямую
- Если строка содержит "n" — парсит как `an+b`

#### `parseNth(s string) (a, b int, ok bool)`

**Назначение:** Парсит строку в формате `an+b` на коэффициенты `a` и `b`.

**Параметры:**
- `s string` — строка для парсинга (например, "2n+1", "3n", "-n+3", "n")

**Возвращаемое значение:**
- `a int` — коэффициент перед `n`
- `b int` — свободный член
- `ok bool` — `true` если парсинг успешен

**Формат:**
- `"2n+1"` → `a=2`, `b=1`
- `"3n"` → `a=3`, `b=0`
- `"-n+3"` → `a=-1`, `b=3`
- `"n"` → `a=1`, `b=0`

**Поведение:**
- Убирает пробелы из строки
- Если строка пуста — `ok=false`
- Если строка не содержит "n" — `ok=false`
- `a` может быть положительным, отрицательным или 1/-1 (для "n")
- `b` может быть любым целым числом

## Внутренние детали реализации

### Структура данных

Функции работают с типом `Node`, который имеет:
- `Parent *Node` — родительский узел
- `Children []*Node` — слайс дочерних узлов
- `Type` — тип узла
- `TagName` — имя тега элемента

Типы узлов:
- `ElementNode` — элемент
- Другие типы (текстовые узлы, комментарии) не учитываются при подсчёте индекса

### Обработка ошибок

Ошибки парсинга обрабатываются неявно — возвращают `ok=false` или `false` для `matchNth`.

### Валидация

- Проверка nil для `n` и `n.Parent`
- Проверка пустых строк
- Проверка формата `an+b` через наличие "n"

### Алгоритм `matchNth`

1. Убирает пробелы и приводит к нижнему регистру
2. Проверяет ключевые слова "even", "odd"
3. Особый случай "0" возвращает `idx == 0`
4. Вызывает `parseNth`
5. Если `parseNth` не валиден — пытается `strconv.Atoi` для чисел
6. Если `a=0` — проверяет `idx == b`
7. Если `a > 0` и `idx < b` — `false`
8. Если `a < 0` и `idx > b` — `false`
9. Проверяет `(idx-b) % a == 0`

## Примеры использования

### Пример 1: childIndex
```go
// Если элемент — третий элемент среди своих сестёр
idx := childIndex(element, false) // 3
```

### Пример 2: lastChildIndex
```go
// Если элемент — второй с конца
idx := lastChildIndex(element, false) // 2
```

### Пример 3: matchNth
```go
// Проверяет, соответствует ли индекс 5 селектору "odd"
matchNth("odd", 5) // true

// Проверяет, соответствует ли индекс 4 селектору "even"
matchNth("even", 4) // true

// Проверяет, соответствует ли индекс 5 селектору "2n+1"
matchNth("2n+1", 5) // true (5 = 2*2 + 1)

// Проверяет, соответствует ли индекс 3 селектору "-n+3"
matchNth("-n+3", 3) // true (3 <= 3)

// Проверяет, соответствует ли индекс 0 селектору "0"
matchNth("0", 0) // true
```

### Пример 4: parseNth
```go
a, b, ok := parseNth("2n+1") // a=2, b=1, ok=true
a, b, ok := parseNth("3n")   // a=3, b=0, ok=true
a, b, ok := parseNth("-n+3") // a=-1, b=3, ok=true
a, b, ok := parseNth("n")     // a=1, b=0, ok=true
a, b, ok := parseNth("")      // a=0, b=0, ok=false
```

## Ограничения и граничные случаи

### childIndex
- Возвращает `0` если узел не найден
- Не учитывает не-элементные узлы
- Case-insensitive сравнение тегов при `ofType=true`

### lastChildIndex
- Возвращает `0` если узел не найден
- Не учитывает не-элементные узлы
- Case-insensitive сравнение тегов при `ofType=true`

### matchNth
- Возвращает `false` для пустых строк
- Возвращает `false` для невалидных форматов
- Обрабатывает отрицательные `a` корректно
- Обрабатывает "0" как специальный случай

### parseNth
- Возвращает `ok=false` если строка не содержит "n"
- Возвращает `ok=false` если строка пуста

## Примечания

- Функции работают только с элементарными узлами (ElementNode)
- Сравнение `TagName` case-insensitive
- Индексы 1-based в соответствии со спецификацией CSS
- `matchNth` не зависит от конкретного узла, только от индекса
