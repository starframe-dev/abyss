# Спецификация: cmd/test_real/main.go

## Обзор

Файл `main.go` в пакете `cmd/test_real` реализует основной входной программой для тестирования реального стека рендеринга (HTML → JS → CSS → Layout → ASCII). Программа принимает список URL-адресов, загружает HTML-контент, выполняет JavaScript-скрипты, вычисляет CSS-стили, строит макет и рендерит результат в ASCII-формате.

## Публичный API

### Функция `main()`

**Подпись:** `func main()`

**Описание:** Входная точка программы. Инициализирует цикл обработки URL-адресов и выводит результат ASCII-рендера для каждого источника.

**Поведение:**
- Создает список URL-адресов для тестирования.
- Для каждого URL выполняет следующую последовательность:
  1. Загружает HTML-контент через `fetcher.Fetch()`.
  2. Парсит HTML через `dom.Parse()`.
  3. Создает контекст JavaScript через `js.NewContext()`.
  4. Инициализирует DOM через `js.InitDOM()`.
  5. Регистрирует мостовые функции через `jsc.RegisterBridgeFunctions()`.
  6. Вычисляет скрипты DOM API через `js.DOMAPIScript()`.
  7. Выполняет скрипты через `js.ExecuteScripts()`.
  8. Закрывает контекст через `jsc.Close()`.
  9. Получает итоговый DOM через `js.GetFinalDOM()`.
  10. Вычисляет CSS-стили через `css.Compute()`.
  11. Строит макет через `layout.Build()`.
  12. Рендерит через `render.Render()`.
  13. Преобразует в ASCII через `ascii.Render()`.
  14. Выводит статистика времени выполнения и содержимое ASCII-рендера.
- Обрабатывает ошибки сети, продолжая обработку остальных URL.

**Параметры:** Нет.

**Возвращаемое значение:** Нет (возвращает `int` через выход из программы).

## Внутренние типы

### Тип `main`

**Описание:** Основной пакет программы, содержащий `main()` и вспомогательные функции.

## Зависимости

### Импорт

- `github.com/starframe/abyss/internal/ascii` — модуль для рендеринга ASCII-графики.
- `github.com/starframe/abyss/internal/css` — модуль для вычисления CSS-стилей.
- `github.com/starframe/abyss/internal/dom` — модуль для парсинга и манипуляций с DOM.
- `github.com/starframe/abyss/internal/fetcher` — модуль для загрузки HTTP-контента.
- `github.com/starframe/abyss/internal/js` — модуль для выполнения JavaScript-кода.
- `github.com/starframe/abyss/internal/layout` — модуль для построения макетов.
- `github.com/starframe/abyss/internal/render` — модуль для рендеринга SVG/изображений.

## Поток выполнения

### Алгоритм обработки URL

1. **Инициализация:**
   - Создается слайс `urls` с тестовыми URL-адресами.

2. **Цикл обработки:**
   - Для каждого URL:
     - Замеры времени выполнения.
     - Запрос HTML-контента.
     - Парсинг HTML в DOM-дерево.
     - Инициализация JavaScript-контекста.
     - Выполнение скриптов.
     - Получение финального DOM.
     - Вычисление стилей.
     - Построение макета (ширина 800px).
     - Рендеринг.
     - Преобразование в ASCII (ширина 800px).
     - Подсчет строк.
     - Вывод результата.

3. **Обработка ошибок:**
   - Ошибки сети обрабатываются с продолжением цикла.
   - Ошибки парсинга или выполнения скриптов обрабатываются в зависимых модулях.

## Статистика

Для каждого URL выводится:
- Размер HTML-документа в байтах.
- Время fetch (загрузки).
- Время парсинга.
- Общее время выполнения.
- Количество строк ASCII-рендера.
- Количество непустых строк.
- Первые 20 непустых строк ASCII.

## Побочные эффекты

- Вывод в стандартный вывод (`fmt.Printf`).
- Создание и удаление объектов (`js.Context`).
- Изменение глобального состояния через `js.GetFinalDOM()`.

## Аргументы командной строки

Файл не принимает аргументы командной строки. URL-адреса заданы внутри программы.

## Побочные эффекты

- Вывод в `stdout` через `fmt.Printf`.
- Создание временных файлов (если применимо).

## Интеграционные точки

- `fetcher.Fetch(url)` — интеграция с HTTP-запросами.
- `dom.Parse(html)` — парсинг HTML.
- `js.NewContext()` — создание изолированного JS-контекста.
- `css.Compute(dom)` — вычисление стилей.
- `layout.Build(dom, styles, width)` — построение макета.
- `render.Render(box, width)` — рендеринг.
- `ascii.Render(fb, box, width)` — ASCII-конвертация.

## Ограничения

- Ширина макета фиксирована на уровне 800px.
- Обработка ошибок не прерывает цикл обработки.
- Максимальное количество выводимых строк ограничено 20 непустыми строками.
