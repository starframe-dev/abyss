# Specification: cmd/debug_ansi/main.go

## Описание

Это утилита для отладки вывода TUI приложения Abyss, которая запускает приложение через cue-tty, удаляет ANSI-коды из логов и проверяет наличие ожидаемых строк в очищенном тексте.

## Общественный API

### Функция: `stripANSI(s string) string`

Удаляет все ANSI-секвенции из строки.

**Параметры:**
- `s` — входная строка, содержащая потенциальный ANSI-кодированный текст

**Возвращаемое значение:**
- Очищенная строка без ANSI-кодов

**Реализация:**
Использует регулярное выражение `\033\[[0-9;]*[a-zA-Z]` для распознавания ANSI-секвенций.

### Функция: `main()`

Точка входа в программу. Запускает цикл отладки для проверки корректности работы TUI.

**Последовательность действий:**

1. **Запуск приложения:**
   - Запускает `./bin/abyss` через `cue.Launch`
   - Установка размера терминала: 120x40
   - Установка рабочего каталога: `/Users/a/Space/Projects/Starframe/abyss`
   - Установка переменной среды: `TERM=xterm-256color`

2. **Проверка начального экрана:**
   - Ожидание стабилизации страницы (2 секунды)
   - Извлечение текста страницы
   - Вывод первых 500 символов текста

3. **Проверка логов на наличие строк:**
   - Извлечение сырого лога из `app.RawLog()`
   - Удаление ANSI-кодов из лога
   - Проверка наличия строки "Abyss"
   - Проверка наличия строки "Enter URL"

4. **Тест загрузки страницы:**
   - Ввод "example.com"
   - Ожидание стабилизации страницы (300мс)
   - Нажатие Enter
   - Ожидание появления "Example Domain" (до 15 секунд с проверкой каждые 200мс)
   - Вывод результата проверки

5. **Завершение:**
   - Нажатие 'q' для выхода
   - Ожидание завершения (500мс)

### Внутренняя функция: `min(a, b int) int`

Вспомогательная функция для вычисления минимального из двух целых чисел.

**Параметры:**
- `a` — первое число
- `b` — второе число

**Возвращаемое значение:**
- Меньшее из `a` и `b`

## Типы

### Константы

Нет явных определений типов. Используются стандартные типы Go.

## Ошибки

Ошибки обрабатываются через возврат из функций и проверку после вызова `cue.Launch`.

- При неудачном запуске приложения: вывод в `stderr` и завершение с кодом 1
- При извлечении текста страницы: результат игнорируется (пустая строка)

## Поведение

### Вводные данные

- Входная строка для `stripANSI` может содержать ANSI-секвенции
- Точка входа `main()` ожидает наличие исполняемого файла `./bin/abyss`

### Выходные данные

- Вывод в `stdout` для отладочной информации
- Вывод ошибок в `stderr`
- Возврат с кодом 1 при неудачном запуске

### Побочные эффекты

- Изменение состояния TUI приложения через `cue.Launch`
- Вывод текста на терминал
- Модификация лога приложения

## Ограничения

- Максимальное время ожидания загрузки страницы: 15 секунд
- Размер терминала фиксирован: 120x40
- Регулярное выражение поддерживает только стандартные ANSI-секвенции

## Тесты

Рекомендуемые сценарии для тестирования:

1. Проверка `stripANSI` с различными входными строками:
   - Строка без ANSI-кодов
   - Строка с одним ANSI-кодом
   - Строка с несколькими ANSI-кодами

2. Проверка `main()`:
   - Корректное запуск приложения
   - Обработка ошибок запуска
   - Проверка наличия ожидаемых строк в логах

## Примечания

- Функция `min` может быть удалена в пользу встроенного `min` из пакета `go/types` или явной проверки в коде
- Регулярное выражение следует проверить на корректность при компиляции
- Тесты следует добавить для проверки обработки ошибок запуска приложения
