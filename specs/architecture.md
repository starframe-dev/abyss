# Архитектура Abyss

## Назначение и границы

Abyss — интерактивный браузерный интерфейс в терминале, написанный на Go. Он загружает веб-страницы и отображает ограниченную поддерживаемую часть HTML/CSS как ANSI-графику с цветом. Это не реализация стандартов браузера целиком: полнота HTML, CSS и JavaScript намеренно ограничена. Подробности отдельных алгоритмов и типов описаны в `code-specs/`.

## Слои

1. `main.go` разбирает параметры запуска. Обычный режим запускает Bubble Tea-приложение; режим `--headless-dump` загружает URL и записывает терминальный вывод в файл. Для headless необходим `--url`; ширина задается `--width`.
2. `internal/browser` — координатор приложения и адаптер к Bubble Tea: модель интерфейса, вкладки, адресная строка, прокрутка, асинхронная загрузка, сообщения результатов, ошибки и сохранение URL сеанса. Здесь же связываются сетевые ресурсы, обработка документа, изображения и отрисовка.
3. `internal/fetcher` предоставляет HTTP-загрузку с контекстной отменой, тайм-аутом, проверкой статуса и отдельными ограничениями размера для HTML, CSS, JS и изображений.
4. `internal/dom` преобразует HTML в собственное дерево узлов, пригодное для запросов селекторами и изменения через JS-мост.
5. `internal/css` разбирает таблицы стилей, сопоставляет правила узлам и вычисляет каскадные стили. Поддерживается подмножество CSS, а не универсальная браузерная модель.
6. `internal/layout` строит дерево геометрических блоков и рассчитывает размеры/позиции, включая реализованные варианты обычного потока, Flexbox, Grid, таблиц и абсолютного позиционирования.
7. `internal/render` рисует блоки и изображения в `internal/framebuffer`, ограниченный RGB-буфер пикселей. `internal/asciirender` декодирует растровые изображения и квантует их в цветные символы; `internal/ascii` преобразует буфер страницы в терминальные строки. `internal/cellmetrics` учитывает ширину символов терминальной ячейки.
8. `internal/browser` подает получившиеся строки в прокручиваемый виджет Bubble Tea. `internal/renderer` — устаревший пакет; новый код использует `internal/render`.

## Сквозной поток данных

Ввод URL инициирует загрузку, привязанную к контексту и идентификаторам вкладки/запроса. Результаты устаревших запросов не должны подменять состояние более нового запроса. После получения HTML формируется DOM; таблицы стилей, ресурсы и поддерживаемые скрипты подключаются в процессе подготовки страницы. Относительные адреса разрешаются относительно базового URL. Стили вычисляются для узлов, затем layout создает дерево коробок. Рендерер окрашивает framebuffer, а ASCII-конвертер формирует строки с ANSI truecolor. Строки передаются модели интерфейса, которая отображает страницу и управляет прокруткой.

Headless-режим использует тот же путь загрузки и представления, но вместо интерактивного TUI сохраняет ANSI-результат. Ошибки сетевого доступа или подготовки страницы передаются модели как результаты загрузки.

## Состояние и конкурентность

Состояние представления принадлежит вкладке: URL, режим, строки вывода, масштаб, смещения и ошибка. Загрузки можно отменять; сообщения несут ID вкладки и запроса для проверки актуальности. Сеанс сохраняет список URL в `~/.abyss/session.json`. Кэш изображений общий и ограниченный по памяти/числу ресурсов. Контексты JavaScript принадлежат вкладкам, но исполнение JS сериализуется; синхронный скрипт нельзя безопасно прервать, поэтому зависший скрипт способен блокировать процесс. Это важное ограничение при работе с недоверенными сайтами.

## Ограничения и инженерные решения

Парсинг и рендеринг рассчитаны на ограниченные ресурсы, а не на совместимость с произвольными сайтами. Лимиты применяются к сетевым ответам, DOM, изображениями, размерам буфера и ресурсам страницы. Неподдерживаемые CSS-конструкции и сложное поведение браузера игнорируются либо отображаются упрощенно. Изображения декодируются с проверкой габаритов, представляются цветными символами; итоговый экран адаптирован к моноширинному терминалу. Сетевой и JS-код не следует считать песочницей.

## Запуск и проверка

Интерактивный запуск: `go run .` (или собранный исполняемый файл). Автономный вывод: `go run . --headless-dump /путь/файл --url https://example.com --width 120`. Тесты проекта запускаются командой `go test ./...`; утилиты в `cmd/` служат для анализа, ручной проверки и интеграционных сценариев. Публичная точка входа приложения — команда в корне; внутренние пакеты предназначены прежде всего для композиции приложения, а не являются стабильным внешним API.
