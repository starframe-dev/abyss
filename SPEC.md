# Полное исправление проблем Starframe Abyss

## Контекст
Репозиторий находится на базовом commit `285c90f` с чистой веткой `main`. Требуется исправить подтверждённые дефекты безопасности, стабильности и корректности терминального браузера на Go, сохранив HTML → DOM → CSS → Layout → Framebuffer → ANSI → Bubble Tea и JavaScriptCore на macOS. Перечень областей и обязательных сценариев задан handoff пользователя.

## Цель
Последовательно улучшить безопасность вывода терминала, ограничить потребление ресурсов и обеспечить автономность бинарника; затем исправить жизненный цикл вкладок, JS, рендеринг и инфраструктуру. Каждое исправление подтверждается детерминированными регрессионными тестами; результаты, непроверенные пункты и ограничения отражаются в итоговом отчёте.

## Что изменится
Изменения будут ограничены относящимися к подтверждённым дефектам компонентами `internal/{js,ascii,browser,fetcher,framebuffer,asciirender}`, тестами и фикстурами, `go.mod`, конфигурацией CueTTY/CI, `.gitignore`, README/инструкциями, benchmarks и этим документом. Точный перечень файлов будет уточняться после аудита реализации. Пользовательские и генерируемые данные не удаляются без анализа.

## Детали реализации
Работать этапами, каждый — воспроизведение тестом, исправление первопричины, целевые и общие проверки, отдельный логический commit:

1. **A — P0:** исследовать пути недоверенного терминального вывода; разрешать только контролируемые SGR от рендерера и безопасно выводить текст/ошибки. Ввести проверяемые лимиты сетевых ответов, изображений после декодирования, DOM-узлов/глубины, CSS-значений/repeat, framebuffer с проверками переполнения, кэш изображений, контексты отмены и ограниченный параллелизм. Встроить JS-ресурсы через `go:embed`.
2. **B — Lifecycle:** исследовать владение JSC/cgo и повторные callback-вызовы до выбора синхронизации. Обеспечить изоляцию состояния вкладок, корректную очистку контекстов/callbacks/timers, идентификацию и отмену устаревших запросов, остановку фоновых процессов и защиту от дублирующихся ticks. Ограничение JS-исполнения реализовать безопасно либо зафиксировать обоснованное ограничение, если JSC не предоставляет безопасного прерывания.
3. **C — Correctness:** добавить тесты и исправить подтверждённые ошибки HTML recovery/fragments, CSS cascade/inheritance/Grid/Flex/media/supports, layout/координат/Unicode, изображений и перерисовки без потери состояния.
4. **D — Performance:** снять воспроизводимые baseline и benchmarks для DOM/CSS/Layout/Rendering/ANSI; менять только подтверждённые горячие пути и сравнивать время и аллокации.
5. **E — Release:** привести module path к `github.com/starframe-dev/abyss`, убрать абсолютные пути CueTTY, настроить macOS CI и проверки, проверить игнорирование генерируемых файлов, обновить документацию и headless-ограничения; выполнить полный аудит и записать результаты.

Для тестов использовать локальные HTTP-серверы и детерминированные фикстуры. Не отключать проверки, не подменять реализации заглушками, не заявлять об успешности непроведённых проверок. Не менять или удалять пользовательские данные без анализа.

## Текущий статус (не считать готовым к релизу)

Официальные Go 1.26.2 (версия из `go.mod` и CI) и Go 1.27.2 arm64 toolchains временно установлены в `/tmp` и проверены по SHA-256. На Go 1.26.2 прошли `go build`, uncached `go test ./...`, uncached `go test -race ./...` и `go vet ./...`; на Go 1.27.2 также пройдены uncached тесты, race и vet. Изменённые Go-файлы отформатированы. После обновления `golang.org/x/net` до v0.60.0 `govulncheck -mode=source ./...` сообщил ноль уязвимостей. `InitDOM` и закрытие текущего JSC-контекста теперь сбрасывают карты DOM/styles/layout старой страницы; при закрытии вкладки отменяется её активный load и освобождается принадлежащий ей текущий JSC-контекст; in-flight `FetchContext` cancellation покрыт deterministic regression. Добавлен ограниченный `dom.ParseFragment`; `innerHTML`, `outerHTML` и `insertAdjacentHTML` используют непосредственные fragment children, включая текст, вместо синтетического wrapper; `getElementById` ищет только подключённые узлы и сохраняет возможность повторно вставить detached node по его NodeID. Image `Quantize` теперь отклоняет исходники сверх лимита пикселей до sampling; изменение ширины viewport инициирует повторный CSS/layout/render pass. Теперь состояние JSC-контекста и DOM/event/timer bridge runtime сохраняется отдельно для каждой вкладки; integration regression загружает две страницы, исполняет независимые таймеры и проверяет, что контексты/DOM не пересекаются. CSS parser учитывает кавычки, escapes и скобки function values при поиске закрывающей скобки rules; CSS cascade учитывает `!important`, inline priority и source order; CSS custom properties разрешаются независимо от порядка объявления, `var()` циклы/глубина ограничены, а вложенность at-rules ограничена 32 уровнями, чтобы исключить переполнение стека на враждебном CSS. `@media` поддерживает `screen` и `min-width`/`max-width` в CSS px с фактической шириной viewport, включая `media` атрибуты `<style>` и `<link>`; неизвестные media features и неподдержанные nested at-rules (`@container`, `@layer`) не применяются безусловно; базовые `@supports` проверки ограничены `display` и `position`. Специфичность учитывает тип перед pseudo/attribute selector и pseudo-elements; пустое `{}` CSS правило игнорируется. Invalid HEX теперь не становится чёрным цветом, а `BoxModel.IsZero` различает нулевые px от auto/percent/fr. Дополнительный `go test -tags legacy ./internal/css` остаётся красным только из-за legacy-ожиданий specificity (например, `div.class1.class2` ожидает 12 вместо CSS-взвешенного 21) и одно-десятичных строк Length при текущей сериализации до двух знаков; обычный CI не включает эти build-tagged тесты. Headless-бинарник успешно запущен из временного каталога вне исходного дерева на локальном fixture. Первый тестовый прогон выявил и помог исправить утечку raw C1 CSI параметров как текста. CueTTY E2E один раз не получил введённый URL; тест теперь проверяет адресное поле, ждёт перехода в `Loading` и повторяет ввод/submit при оставшемся address mode; 10 последовательных запусков предыдущей версии helper и 5 повторов текущей версии прошли. Измерен baseline и подтверждена ANSI-оптимизация: около 39.3% быстрее, на 40.2% меньше байтов и на 97.3% меньше аллокаций на fixture. Это не полная приёмка: JavaScriptCore и DOM/event/timer bridge state теперь сохраняются отдельно на вкладку, но их выполнение сериализовано; бесконечный синхронный JS безопасно не прерывается и блокирует остальные вкладки. В установленном публичном `JSContextRef.h` просмотрены доступные C API; execution-time-limit/termination API не обнаружен, а освобождать контекст во время синхронного вызова небезопасно. Grid `fr` распределяется при явной высоте; фиксированные/процентные tracks больше не растут от переполнения items, implicit rows и Grid без явных row tracks получают intrinsic auto sizing. Полная CSS Grid track sizing semantics (включая spanning/placement и minmax) не реализована. Для `flex-direction: column` добавлены main-axis `justify-content` и распределение flex-grow при definite height; flex-shrink по column, align-items и полный flex-basis spec остаются частичными. Unicode также покрыт не полностью. Commits `6b34a56` и `b188c88`: `-webkit-box`/`-webkit-flex` сопоставляются с flex; текст рядом с блочными детьми сохраняется в анонимном inline-боксе; `<input>` выводит value, затем placeholder/title, `type=hidden` не выводится. google.com по-прежнему рендерится частично (нет полной совместимости с Google). Commit `f6d0bb4` добавляет изолированные per-tab JSC runtimes, snapshot/restore DOM/styles/layout/events/timers и integration regression на две страницы; `5287f6a` исправляет fixed/implicit Grid track sizing; `40c379f` чинит column flex justification; `893aa60` распределяет column flex-grow. Commits `fd3c865` (Graphloom cleanup), `85fe243` (macOS CI/документация), `134f537` (CSS cascade и bounded `var()`), `db829d8` (статус отчёта) и `4204a29` (security/lifecycle/CSS/layout regressions и gofmt), `7d3586d` (ограничение входа image quantizer) и `37bb19d` (HTML fragments и connected ID lookup) и `eaf531a` (rerender при resize и устойчивый CueTTY E2E), `45d9892` (учёт quoted/escaped braces в CSS parser) и `20e33f0` (in-flight fetch cancellation), `58a4e9f` (закрытие owner-tab очищает JSC) и `2b92796` (не регистрировать отвергнутые fragment-вставки) и `f887716` (balance braces вне CSS functions) фиксируют основные результаты этапов. 357 Graphloom-файлов сохранены на диске; рабочее дерево после commit чистое. Все локальные CI-equivalent проверки прошли, но GitHub Actions удалённо не запускался; перед релизом нужны code review, закрытие оставшихся рисков и проверка workflow в GitHub.

## Google.com: текущие ограничения (commits 6b34a56, b188c88, 6482be8, 522030d)

- `-webkit-box` и `-webkit-flex` сопоставляются с `display: flex`.
- Текст рядом с блочными дочерними элементами выводится в анонимном inline-боксе.
- `<input>` выводит `value`, затем `placeholder`/`title`; `type=hidden` не выводится.
- Высота изображения берётся из layout-бокса, а не из строки alt-текста.
- Относительные `<img src>` переписываются на абсолютный URL, чтобы совпасть с ключом кэша декодированных изображений. Без этого логотип декодировался, но не рисовался.
- Логотип google.com выводится грубым ASCII-квантованием; это ожидаемое ограничение терминала.
- Полная совместимость с google.com не достигнута: страница рендерится частично, многие блоки и стили Google не поддерживаются.
- Квантование ramp для тёмных пикселей отдельно не сравнивалось; замер показал видимые ячейки, но не качество градаций.

## Google.com: логотип и футер (статус)

- Логотип: тест `TestLogoQuantizationKeepsVisibleGlyphs` (`asciirender`) подтверждает видимые глифы при 20/40/60 колонках. Исправление квантования не потребовалось.
- Футер: ссылки внутри `div` выкладываются по одной в строку (y=0, 2, 4), а не потоком. Причина: в Abyss нет браузерного значения `display:inline` по умолчанию для `a`/`span`, поэтому их дочерние боксы считаются блоками. Красный тест `TestFooterLinksWrapWithinWidth` не закоммичен; попытка обойти через проверку «все дети inline» не сработала и откатана.
- Исправление требует задать inline-умолчания для тегов (`a`, `span`, `b`, `i` и др.). Это меняет раскладку всех страниц и требует отдельного этапа с полным прогоном тестов.
