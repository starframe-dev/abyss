# `internal/layout`

Пакет `layout` строит дерево геометрической компоновки на основе DOM-дерева и вычисленных стилей CSS. Он реализует намеренно компактную CSS-блочную модель и поток текста для рендерера, включая блочные, строчные, flex-, grid- и табличные элементы, изображения и отдельные элементы управления формами.

## Публичный API

### `ViewportWidth`

```go
const ViewportWidth = 800
```

Ширина области просмотра по умолчанию в пикселях CSS. `Build` принимает явную ширину; вызывающим сторонам следует использовать эту константу, если им требуется ширина пакета по умолчанию.

### `Rect`

```go
type Rect struct {
    X, Y, Width, Height float64
}
```

Прямоугольник в координатах пикселей CSS. Прямоугольники в `LayoutBox` описывают соответственно области содержимого, внутреннего отступа, границы и внешнего отступа. Координаты `Content` являются абсолютными координатами компоновки, несмотря на историческую формулировку комментария, называющую их относительными области содержимого родителя.

### `TextLine`

```go
type TextLine struct {
    Text string
    X, Y float64
}
```

Фрагмент текста, позиционированный для отображения. Измерение и перенос текста используют ширину ячеек терминала из `go-runewidth` и размеры в пикселях из `internal/cellmetrics`.

### `LayoutBox`

```go
type LayoutBox struct {
    Node      *dom.Node
    Parent    *LayoutBox
    Style     css.ComputedStyle
    Content   Rect
    Padding   Rect
    Border    Rect
    Margin    Rect
    Children  []*LayoutBox
    TextLines []TextLine
    AsciiCells [][]asciirender.Cell
}
```

Узел DOM, для которого выполнена компоновка. `Node` и `Style` сохраняют исходный узел и его вычисленный стиль; `Parent` и `Children` образуют дерево компоновки. Четыре прямоугольника описывают геометрию блочной модели. `TextLines` содержит позиционированный текст, созданный во время компоновки. `AsciiCells` предназначено для декодированного содержимого изображений и заполняется функцией `render.Render`, а не процедурами компоновки этого пакета.

### `Build`

```go
func Build(doc *dom.Node, styles map[*dom.Node]css.ComputedStyle, viewportWidth float64) *LayoutBox
```

Создаёт дерево компоновки и вычисляет его геометрию с использованием заданной ширины области просмотра. Стили ищутся по указателю на узел DOM. Для отсутствующих записей используется `css.Default()`. Текстовые узлы обычно не являются самостоятельными блоками; текст, содержащий непробельные символы и расположенный рядом с дочерними элементами, сохраняется посредством анонимных строчных блоков. Элементы `style`, `script` и `head`, а также узлы с `display: none` исключаются. Возвращает `nil`, если корневой узел документа исключён; в противном случае возвращает корень с выполненной компоновкой.

### `Layout`

```go
func Layout(box *LayoutBox, containerWidth float64)
```

Вычисляет геометрию существующего дерева компоновки на месте. Корень располагается в начале координат, а `containerWidth` задаёт доступную ширину для вычисления размеров `auto` и процентных размеров. Функция не возвращает ошибку; вызывающие стороны отвечают за передачу корректного блока и подходящих размеров.

## Поведение компоновки

### Построение дерева и блочная модель

Построитель сохраняет нефильтрованные узлы-элементы, задаёт указатели на родителей и инициализирует каждый блок пустым срезом дочерних элементов. Контейнеры, содержащие только текст, компонуются на основе строчного текста потомков. При смешанном содержимом из элементов и текста значимый текст между соседними узлами оборачивается в анонимный строчный блок, который наследует стили текста, но сбрасывает ширину, высоту, внешние и внутренние отступы, границы и фон к значениям по умолчанию. Это предотвращает повторное применение блочной модели родителя.

Для каждого блока компоновка вычисляет ширину относительно ширины содержащего блока. Автоматическая ширина заполняет контейнер за вычетом горизонтальных внешних отступов и ограничивается нулём снизу. Для изображений с автоматической шириной CSS вместо этого может использоваться положительное числовое значение атрибута `width`. Поля кнопок отправки (`submit`, `button` или `reset`) с автоматической шириной подгоняются под подпись и горизонтальные внутренние отступы. Ширина содержимого равна вычисленной ширине за вычетом внутренних отступов и границ и также ограничивается нулём снизу. Прямоугольники строятся наружу от позиции границы; позиция корня начинается в начале координат. Внешние и внутренние отступы вычисляются относительно ширины содержащего блока.

Высота определяется компоновкой содержимого, если в CSS не задана высота, отличная от `auto`. Высоты областей внутреннего отступа, границы и внешнего отступа включают соответствующие вертикальные внутренние отступы, границы и внешние отступы. Абсолютное позиционирование использует ближайшего предка с позиционированием `relative` или `absolute`. Явные значения `left`/`top` имеют приоритет; значения `right` и `bottom` позиционируют блок, если соответствующее значение `left`/`top` равно `auto`.

### Поток содержимого

Дочерние элементы обрабатываются в зависимости от типа узла и типа отображения:

- Для изображений используется компоновка текстовой заглушки.
- Таблицы передаются процедуре компоновки таблиц.
- Flex- и grid-блоки передаются соответствующим процедурам.
- Блочные блоки и `inline-block` используют блочный поток; если дочерних элементов блочного потока нет, используется строчное содержимое.
- Для остальных блоков используется строчный поток.

Блочный поток размещает обычные дочерние элементы вертикально. Последовательности похожих на кнопки элементов управления, текстовых ссылок и видимых текстовых узлов располагаются в общих строках и переносятся при исчерпании доступной ширины. Узлы, содержащие только пробелы, между элементами строки не прерывают последовательность. Строки учитывают выравнивание по центру у `<center>` или `align="center"`, а в остальных случаях — выравнивание текста блока; между соседними текстовыми ссылками добавляется явный интервал.

Строчный поток объединяет видимый текст, разбивает его на слова и выполняет перенос с учётом ширины отображения в терминале. Каждая строка позиционируется от начала области содержимого блока с вертикальным шагом `cellmetrics.HeightPx`. Потомки `script` и `style` исключаются. Скрытые поля не добавляют содержимое. Поля ввода отображают своё значение, а при его отсутствии — подсказку; пустые поля ввода и текстовые области сохраняют одну видимую строку. Для поисковых полей ввода (в том числе с `name="q"`) без подписи отображаются простые ASCII-значки поиска или элемента управления.

Изображения отображают переносимую подпись `[image]`, основанную на атрибуте `alt`; по умолчанию используется `image`. Положительное числовое значение атрибута высоты задаёт высоту содержимого изображения, но не менее 48 пикселей CSS; в противном случае высота определяется числом строк после переноса.

## Важные детали реализации

- Компоновка ориентирована на рендерер и не является полной реализацией CSS браузера. Поддерживаются явно реализованные здесь случаи; для разобранных значений стилей используется `css.ComputedStyle`.
- При вычислении ширины и текста используется `runewidth.StringWidth`, поэтому широкие символы Unicode занимают несколько ячеек терминала.
- Процентные внешние и внутренние отступы вычисляются относительно ширины содержащего блока, включая вертикальные значения.
- `TextLines` создаются во время компоновки, а ASCII-ячейки изображений добавляются позднее уровнем рендеринга.
- Внутренние вспомогательные функции реализуют классификацию строк, подписи элементов форм, сбор текста, перенос и поиск позиционированного предка; они не входят в экспортируемый API.
