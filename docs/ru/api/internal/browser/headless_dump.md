# `internal/browser/headless_dump.go`

## Обзор

Этот файл предоставляет безголовую точку входа для преобразования загруженной веб-страницы в дамп с ANSI-графикой. Он выполняет этапы загрузки и отрисовки страницы браузером, не запуская терминальный интерфейс, что удобно для детерминированных сквозных проверок, которым не требуется PTY.

## Публичный API

### `HeadlessDump(pageURL string, width int, outputPath string)`

Загружает `pageURL`, обрабатывает документ и его ресурсы, отрисовывает его с заданной шириной терминала и записывает полученный ANSI-текст в `outputPath`.

| Аргумент | Значение |
| --- | --- |
| `pageURL` | URL загружаемой страницы. |
| `width` | Ширина вывода в ячейках терминала. Конвейер отрисовки преобразует её в пиксели с помощью `cellmetrics.WidthPx`. |
| `outputPath` | Путь к файлу для сохранения ANSI-дампа. |

Функция не возвращает значения. Ошибки загрузки и записи выводятся в стандартный поток ошибок и завершают процесс с кодом 1 через `os.Exit`; вызывающий код не может обработать их как возвращаемые значения. При успешном выполнении в стандартный поток ошибок выводится сообщение с размером дампа в байтах и путём назначения.

## Последовательность обработки

1. Сбрасывает кэш изображений и устанавливает `render.ImageProvider` в кэшированный провайдер изображений браузера.
2. Загружает HTML страницы с помощью `fetcher.Fetch`.
3. Разбирает HTML в DOM и загружает изображения, на которые ссылается документ.
4. Загружает внешние CSS-файлы и вычисляет стили для ширины `width * cellmetrics.WidthPx` пикселей.
5. Строит макет на основе вычисленных стилей и той же ширины в пикселях.
6. Отрисовывает макет в кадровый буфер указанной ширины.
7. Преобразует кадровый буфер и макет в строки ANSI с помощью `ascii.RenderANSI`.
8. Объединяет строки символами новой строки и записывает результат с правами `0644` (с учётом маски режима процесса).

Функция не запускает TUI и не взаимодействует с ним. Настройка отрисовки использует переменную уровня пакета `render.ImageProvider`, поэтому эта операция изменяет общее состояние пакета; при параллельных вызовах или другой работе по отрисовке в том же процессе следует учитывать совместное использование этого состояния.

## Вывод и ошибки

Выходной файл содержит объединённые строки ANSI и не получает дополнительный символ новой строки после последней строки. Создание и замена файла выполняются согласно поведению `os.WriteFile`. Ошибки загрузки выводятся с префиксом `headless dump: fetch:`, ошибки записи — с префиксом `headless dump: write:`. В обоих случаях выполнение немедленно завершается с кодом 1. При успешном выполнении в стандартный поток ошибок выводится сообщение `headless dump: <bytes> bytes -> <path>`.
