# `internal/ascii`

Пакет `ascii` преобразует содержимое framebuffer и layout в текст, удобный для отображения в терминале. Он поддерживает вывод как обычного текста, так и текста с ANSI-цветами True Color, сохраняя кластеры графем Unicode и их ширину в ячейках терминала.

## Публичный API

### `Cell`

Представляет одну ячейку терминала. Также используется как промежуточное представление при создании вывода.

| Поле | Тип | Значение |
|---|---|---|
| `Char` | `rune` | Начальная руна, отображаемая в ячейке. При рендеринге нулевая руна считается пробелом. |
| `Extra` | `string` | Остальные руны того же кластера графем, например комбинируемые знаки или соединители. |
| `Width` | `int` | Ширина кластера в столбцах терминала. Если значение не положительное, ширину вычисляет рендерер. |
| `Continuation` | `bool` | Обозначает ячейку, занятую вторым столбцом широкой графемы; при выводе она пропускается. |
| `FG` | `css.Color` | Цвет переднего плана. |
| `BG` | `css.Color` | Цвет фона. |

### `Render`

```go
func Render(fb *framebuffer.Framebuffer, tree *layout.LayoutBox, viewportWidth int) []string
```

Преобразует содержимое framebuffer и layout в строки обычного текста. Ширина области просмотра ограничивается снизу нулём. Если framebuffer равен `nil` или его ширина в пикселях равна нулю, возвращается срез из одного пустого строкового значения. В остальных случаях framebuffer преобразуется в сетку терминальных ячеек, затем применяются текст layout и наложения ASCII-ячеек, после чего строки выводятся с учётом запрошенной ширины. Обычный вывод не содержит ANSI-последовательностей цвета.

### `RenderANSI`

```go
func RenderANSI(fb *framebuffer.Framebuffer, tree *layout.LayoutBox, viewportWidth int) []string
```

Использует ту же сетку и те же наложения, что и `Render`, но добавляет ANSI escape-последовательности для заданных цветов переднего плана и фона. Строки дополняются пробелами до ширины области просмотра и завершаются ANSI-последовательностью сброса. Для пустого framebuffer и ограничения ширины действуют те же правила.

## Поведение при рендеринге

Framebuffer преобразуется в сетку с использованием общих размеров `cellmetrics`. Для каждой терминальной ячейки берётся цвет пикселя framebuffer в её центре. Высота сетки округляется вверх, чтобы включить последнюю неполную строку пикселей; ширина учитывает только полностью помещающиеся ячейки терминала. Если цвет пикселя задан, ячейка представляется пробелом с этим цветом фона; незаданные цвета остаются прозрачными.

Наложения layout применяются в два этапа:

1. В сетку копируются предварительно квантованные ASCII-ячейки из блоков layout. Блоки с абсолютным позиционированием пропускаются, поэтому иконки поверх полей не перекрывают поля в терминальном выводе. Ячейки за пределами сетки игнорируются.
2. Строки текста рекурсивно собираются из дерева layout и размещаются согласно пиксельным координатам, преобразованным в строки и столбцы терминала. Для текста используется цвет стиля блока, а если он не задан — тёмно-серый (`RGB(30, 30, 30)`). Существующие цвета фона ячеек сохраняются. Текст за пределами строки обрезается; для двухколоночных графем вторая ячейка помечается как продолжение.

Текст обрабатывается как кластеры графем Unicode, а не как отдельные байты. Ширина кластера определяется с помощью `uniseg`; если ширина ячейки отсутствует или не положительна, она вычисляется через `go-runewidth`. Непечатаемые символы заменяются на `�`. Хвосты кластеров ограничиваются печатаемыми рунами и выбранными соединителями нулевой ширины и селекторами варианта, чтобы небезопасные управляющие символы не попадали в вывод.

При обычном рендеринге строки выводятся без дополнения до ширины области просмотра. Если следующая графема превысит заданную ширину, вместо неё выводится пробел и обработка строки прекращается. ANSI-рендеринг также не разделяет широкие графемы, заменяет пробелом графему, которая не помещается, и дополняет оставшуюся ширину. Для изменения цвета ANSI используются 24-битные параметры переднего плана (`38;2`) и фона (`48;2`); в конце строки состояние цвета сбрасывается.

## Примечания по реализации

- Сетка — внутреннее представление для рендеринга; `makeGrid`, вспомогательные функции наложения и сериализации не экспортируются.
- `colorsEqual` сравнивает как состояние заданности цвета, так и компоненты RGB.
- ANSI-последовательности формируются с помощью `strings.Builder`; байтовые компоненты RGB форматируются напрямую как десятичные цифры.
- Пакет использует типы `framebuffer`, `layout`, `cellmetrics` и `css` для исходных пикселей, геометрии, размеров ячеек и цветов.
