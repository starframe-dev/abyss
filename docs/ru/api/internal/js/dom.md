# Состояние моста JavaScript DOM

`internal/js/dom.go` реализует состояние DOM на стороне Go, используемое мостом JavaScriptCore. Он связывает идентификаторы узлов, доступные JavaScript, с узлами `internal/dom`, поддерживает состояние моста для каждой страницы и предоставляет вспомогательные функции для изменения и поиска, используемые другими файлами пакета. Большинство функций DOM не экспортируются; здесь они описаны как API реализации, а не как API, вызываемый из внешних пакетов.

## Публичный API

| Имя | Описание |
| --- | --- |
| `NodeID` | Целочисленный идентификатор, присвоенный узлу DOM для операций моста. |
| `Rect` | Прямоугольник макета со значениями `X`, `Y`, `Width` и `Height` типа `float64`. |
| `Runtime` | Снимок контекста JavaScript и состояния моста одной неактивной страницы. |
| `SetCurrentContext` | Устанавливает активный контекст и URL, закрывая предыдущий отличный от него контекст. |
| `GetCurrentContext` | Возвращает активный контекст и его URL. |
| `CaptureRuntime` | Отсоединяет контекст активной страницы и состояние её моста, помещая их в `Runtime`. |
| `ActivateRuntime` | Восстанавливает захваченный runtime в качестве активной страницы. Игнорирует nil-runtime. |
| `CloseRuntime` | Активирует отсоединённый runtime и закрывает его, освобождая обратные вызовы и состояние DOM. |
| `CloseCurrentContext` | Закрывает активный контекст JavaScriptCore и сбрасывает состояние DOM. |
| `SetDirty` | Помечает DOM как изменённый. |
| `IsDirty` | Сообщает, помечен ли DOM как изменённый. |
| `MarkClean` | Сбрасывает флаг изменений, обычно после отрисовки. |
| `InitDOM` | Сбрасывает состояние DOM моста и регистрирует узлы разобранного документа. |

Поля `Runtime` не экспортируются; вместо манипуляций содержимым снимка вызывайте функции захвата, активации и закрытия.

## Состояние и жизненный цикл

Мост хранит на уровне пакета состояние активного контекста и URL, сопоставления идентификаторов узлов, корневой документ, вычисленные стили, прямоугольники макета, обратные вызовы событий, таймеры и флаг изменений. Мьютексы защищают эти отдельные группы состояния. На уровне жизненного цикла браузер отвечает за последовательное выполнение активации и JavaScript; мьютексы не обеспечивают безопасность произвольных параллельных операций с DOM вместо этого требования.

`CaptureRuntime` переносит (а не копирует) активный контекст и карты/срезы состояния в новый runtime, а затем очищает состояние на уровне пакета. `ActivateRuntime` выполняет обратный перенос и опустошает снимок. Поэтому runtime представляет отсоединённое состояние; его нельзя активировать параллельно или многократно, как если бы это была неизменяемая копия. При активации вызывающий код должен обеспечить отсутствие активного runtime другой страницы.

При замене ненулевого активного контекста на другой в `SetCurrentContext` сбрасывается система событий и закрывается старый контекст. `CloseCurrentContext` также сбрасывает обработку событий, при наличии закрывает текущий контекст и сбрасывает состояние узлов, стилей, макета и изменений. Жизненный цикл контекста runtime и очистка обратных вызовов согласуются с другими файлами моста.

## Идентификация узлов и инициализация

`InitDOM` очищает имеющееся состояние DOM, макета и стилей, задаёт переданный узел как корневой документ и рекурсивно регистрирует его и его потомков. Идентификаторы начинаются с `1`; карты обеспечивают поиск в обоих направлениях. Регистрация прекращается, когда число зарегистрированных узлов достигает `dom.MaxDOMNodes`; при неудачной регистрации возвращается значение-сентинел `-1`. Новые элементы, текстовые узлы, фрагменты и потомки разобранного inner HTML получают идентификаторы через тот же реестр.

`Rect` — структура значения, используемая мостом вычисленного макета. Вычисленные стили и блоки макета хранятся отдельно от реестра узлов DOM и переносятся вместе со снимком runtime.

## Операции DOM

Неэкспортируемые вспомогательные функции составляют внутренний интерфейс моста для изменения и поиска:

- `createElement` приводит имя тега к нижнему регистру и создаёт элемент с инициализированными коллекциями атрибутов и потомков.
- `createTextNode` создаёт текстовый узел с переданным текстом.
- `createDocumentFragment` создаёт фрагмент с именем `#document-fragment`.
- `appendChild` проверяет оба идентификатора, запрещает добавление узла к самому себе и циклы, отсоединяет обычного потомка от прежнего родителя, а затем добавляет его. При добавлении фрагмента его потомки перемещаются в целевой узел (сам фрагмент не вставляется); если какой-либо потомок фрагмента создал бы цикл, операция отклоняется.
- `setInnerHTML` разбирает разметку с помощью `dom.ParseFragment`, удаляет имеющихся потомков и отсоединяет их, затем вставляет непосредственных потомков результата разбора и регистрирует их потомков. Сам целевой узел не заменяется.
- `setAttribute` приводит имя атрибута к нижнему регистру и сохраняет значение, при необходимости инициализируя карту атрибутов.
- `setTextContent` удаляет имеющихся потомков и отсоединяет их, затем добавляет новый текстовый узел. Ничего не делает для неизвестного идентификатора или если уже достигнут предел числа узлов.
- `removeChild` удаляет указанный узел, только если он является непосредственным потомком указанного родителя, и очищает указатель на родителя. Узел не удаляется из карт идентификаторов.
- `getBody` ищет непосредственный элемент `html` под корневым документом, а затем его непосредственного потомка `body`; если такая структура отсутствует, возвращает nil.
- `getElementByID` рекурсивно ищет в дереве корневого документа первый элемент, значение атрибута `id` которого совпадает с переданным.
- `getNodeID` возвращает идентификатор зарегистрированного узла или `-1`; `getAttribute` возвращает значение атрибута либо пустую строку для неизвестного узла.

Недопустимые идентификаторы и отклонённые структурные изменения обычно приводят к отсутствию действий либо к возврату значения-сентинела/пустого значения, а не к ошибке. Не следует считать, что пустое значение атрибута означает наличие атрибута с пустым значением.

## Детали реализации

Операции с деревом узлов используют `nodeMu`; вспомогательные функции, имена которых оканчиваются на `Locked`, требуют удерживать этот мьютекс. Обнаружение циклов проходит вверх от предполагаемого родителя по ссылкам `Parent`. Перемещение потомков сохраняет идентичность каждого потомка и обновляет указатель на родителя. Удалённые и заменённые узлы остаются зарегистрированными в карте идентификаторов, поэтому в течение жизненного цикла DOM идентификаторы не переиспользуются. Общий предел регистрации действует как при первоначальном обходе, так и при последующем создании узлов.

Модуль использует типы ссылок на объекты и контексты JavaScriptCore из cgo для обратных вызовов событий и таймеров. Эти ссылки сохраняются в состоянии runtime; их жизненный цикл обрабатывается совместно с жизненным циклом контекста JavaScript. Запись `timer` содержит идентификатор, ссылку на обратный вызов, срок срабатывания, интервал и флаг повтора для моста таймеров.
