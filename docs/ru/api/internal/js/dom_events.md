# DOM-события и таймеры

Этот файл пакета реализует реестры обработчиков событий и таймеров на основе JavaScriptCore для моста DOM/runtime. Он защищает объекты JavaScript-колбэков от сборки мусора, пока они зарегистрированы, вызывает колбэки через JavaScriptCore и снимает эту защиту при удалении регистраций или сбросе системы событий.

## Публичный API

| Функция | Поведение |
| --- | --- |
| `InitEventSystem(ctx C.JSGlobalContextRef)` | Сбрасывает предыдущее состояние системы событий, устанавливает переданный глобальный контекст JavaScriptCore, инициализирует пустой реестр обработчиков и вызывает `MarkClean()`. |
| `AddEventListener(nodeID NodeID, eventType string, callback C.JSObjectRef)` | Регистрирует колбэк для указанного типа события на узле. Повторные регистрации сохраняются независимо друг от друга. |
| `RemoveEventListener(nodeID NodeID, eventType string, callback C.JSObjectRef)` | Удаляет первую совпадающую ссылку на колбэк для данного узла и типа события. Если узел, тип события или колбэк отсутствует, ничего не происходит. |
| `ProcessTimers() bool` | Выполняет все таймеры, срок которых наступил. Возвращает `false`, если готовых таймеров нет, и `true`, если был вызван хотя бы один колбэк. Вызывающая сторона должна обеспечить активность соответствующего контекста JavaScriptCore. |

`NodeID` и `C.JSGlobalContextRef` / `C.JSObjectRef` предоставляются окружающим мостом JavaScript; этот файл не определяет дополнительных публичных типов данных.

## Диспетчеризация событий

`dispatchEvent(nodeID, eventType)` — функция, доступная только внутри пакета. Она копирует зарегистрированные колбэки, удерживая мьютекс событий, а затем освобождает блокировку перед вызовом JavaScript. Это позволяет не удерживать блокировку реестра во время вызовов внешней среды выполнения. Колбэки вызываются в порядке регистрации с одним аргументом — вновь созданным объектом события. Вызов выполняется с нулевым значением `this`.

Объект события содержит:

- `type`: строка с типом события;
- `defaultPrevented`, изначально равное `false`;
- `preventDefault()`: устанавливает `defaultPrevented` в `true`;
- `stopPropagation()`: устанавливает внутренний флаг `_propagationStopped` в `true`.

После каждого колбэка диспетчеризация проверяет `_propagationStopped` и прекращает вызов последующих колбэков, если значение истинно. `defaultPrevented` доступно потребителям, но в этой реализации никак не влияет на диспетчеризацию. Исключения JavaScript передаются в выходной параметр исключения JavaScriptCore, но здесь никак иначе не обрабатываются.

Объект события создаётся вычислением JavaScript-выражения в активном контексте. Если вычисление возвращает нулевой результат, `makeEventObject` возвращает JavaScript-значение `null`.

## Таймеры

Функции `setTimeout(callback, delayMs)` и `setInterval(callback, delayMs)`, доступные только внутри пакета, выделяют монотонно возрастающие целочисленные идентификаторы и регистрируют защищённые колбэки со сроками, рассчитанными на основе `time.Now()`. Обе интерпретируют задержку в миллисекундах. Таймер `timeout` срабатывает один раз; `interval` повторяется с той же длительностью интервала. `clearTimer(id)` удаляет соответствующий таймер и снимает защиту с его колбэка; неизвестные идентификаторы игнорируются.

`ProcessTimers` под блокировкой мьютекса таймеров разделяет список на готовые и ожидающие таймеры, а затем вызывает готовые колбэки вне блокировки, без аргументов и с нулевым значением `this`. После вызова защита с колбэков однократных таймеров снимается. Повторяющиеся таймеры планируются снова: срок рассчитывается как зафиксированное на начало прохода время обработки плюс интервал. Таким образом, это механизм опроса: таймеры запускаются только при вызове `ProcessTimers` со стороны хоста, а повторяющиеся таймеры не компенсируют пропущенные интервалы. Исключения колбэков эта функция не передаёт.

## Жизненный цикл контекста и владение колбэками

`resetEventSystem` и `resetEventSystemForContext` — вспомогательные функции жизненного цикла, доступные только внутри пакета. Сброс снимает защиту с колбэков обработчиков и таймеров, используя старый контекст JavaScriptCore, очищает состояние обработчиков и таймеров и сбрасывает идентификаторы таймеров. Вариант для конкретного контекста ничего не делает, если ожидаемый контекст не равен `nil` и отличается от установленного в данный момент контекста. `InitEventSystem` перед установкой нового контекста выполняет безусловный сброс.

Обработчики хранятся по ID узла и типу события; таймеры хранятся в общей последовательности. Операции с реестрами используют мьютексы, а выполнение колбэков JavaScript происходит после снятия блокировок. Контекст событий должен оставаться действительным, пока колбэки защищаются, освобождаются или вызываются. В частности, для `ProcessTimers` требуется активный текущий контекст.
