# Мост событий и таймеров JavaScript

В `internal/js/bridge_events.go` реализованы адаптеры для JavaScript, предназначенные для операций с таймерами и событиями узлов. Каждый адаптер получает оболочку контекста JavaScriptCore (`*Context`) и срез значений JavaScriptCore, преобразует необходимые аргументы для внутренней системы событий и возвращает значение JavaScriptCore.

Эти функции являются закрытыми деталями реализации пакета. Мост регистрирует их имена в глобальном окружении JavaScript; они не являются экспортируемыми методами Go API.

## Функции моста JavaScript

| Имя JavaScript | Адаптер Go | Аргументы | Результат |
| --- | --- | --- | --- |
| `setTimeout` | `setTimeoutJS` | обратный вызов, задержка в миллисекундах | Числовой идентификатор таймера; `0`, если аргументы отсутствуют или преобразование обратного вызова не удалось |
| `setInterval` | `setIntervalJS` | обратный вызов, задержка в миллисекундах | Числовой идентификатор таймера; `0`, если аргументы отсутствуют или преобразование обратного вызова не удалось |
| `clearTimeout` | `clearTimeoutJS` | идентификатор таймера | `undefined` |
| `clearInterval` | `clearIntervalJS` | идентификатор таймера | `undefined` |
| `addEventListener` | `addEventListenerJS` | идентификатор узла, тип события, обратный вызов | `undefined` |
| `removeEventListener` | `removeEventListenerJS` | идентификатор узла, тип события, обратный вызов | `undefined` |
| `dispatchEvent` | `dispatchEventJS` | идентификатор узла, тип события | `undefined` |

Настройка моста в `bridge.go` регистрирует адаптеры под этими именами. Имена обеспечивают доступ в стиле JavaScript к системе событий Go; этот файл не определяет цели событий на уровне языка JavaScript и не гарантирует совместимость с браузерами за пределами описанного здесь поведения.

## Обработка аргументов

- Адаптерам таймеров требуется не менее двух аргументов. Первый преобразуется в объект JavaScriptCore и не должен быть `null`. Задержка преобразуется с помощью `Context.ToNumber`; при ошибке преобразования используется `0`. Полученное число преобразуется в Go `int` без дополнительных проверок диапазона или знака.
- Адаптерам очистки требуется не менее одного аргумента. Если его числовое преобразование успешно, значение преобразуется в `int` и передаётся общей функции очистки таймеров. Отсутствующие или нечисловые идентификаторы игнорируются.
- Адаптерам событий требуется указанное количество аргументов. Идентификатор узла преобразуется с помощью `jsToNodeID`; отрицательный результат приводит к пропуску операции. Тип события извлекается через `getArgString`; ошибка игнорируется, поэтому используется строка, возвращённая помощником, даже если преобразование завершилось ошибкой.
- Обратные вызовы слушателей должны преобразовываться в ненулевой объект JavaScriptCore. В противном случае регистрация или удаление игнорируется.
- Недопустимые или неполные вызовы возвращают те же значения по умолчанию, что и соответствующие корректные вызовы: при раннем сбое создание таймера возвращает числовой ноль, а операции очистки и обработки событий — `undefined`.

## Поведение событий

Адаптеры делегируют работу подсистеме событий в `dom_events.go`. Слушатели связываются с идентификатором узла и строкой типа события. При отправке события зарегистрированные обратные вызовы вызываются с одним объектом события в качестве аргумента. Этот объект предоставляет свойства `type`, `defaultPrevented` и методы `preventDefault()`, `stopPropagation()`; вызов `stopPropagation()` прекращает дальнейший вызов обратных вызовов для этой отправки. Регистрация и удаление слушателей выполняются по идентичности обратного вызова; удаление убирает одну совпадающую регистрацию. Сами адаптеры моста не сообщают, найден ли слушатель и были ли вызваны какие-либо обратные вызовы при отправке.

## Поведение таймеров

Создание таймера делегируется общей очереди таймеров и возвращает его целочисленный идентификатор как число JavaScript. `setTimeout` планирует однократный вызов обратного вызова, а `setInterval` — повторяющийся. Оба адаптера очистки вызывают одну и ту же внутреннюю операцию `clearTimer`, поэтому любое из этих имён может очистить таймер, созданный любой из функций создания. Фактическое выполнение обрабатывается функцией `ProcessTimers` в подсистеме событий, а не адаптерами моста; хост должен обрабатывать таймеры при активном контексте JavaScript.

## Типы и примечания по реализации

- `Context` — оболочка пакета для контекста JavaScriptCore; она предоставляет методы преобразования значений и создания значений JavaScript, например `ToNumber`, `MakeNumber` и `MakeUndefined`.
- `C.JSValueRef` представляет входящие значения JavaScript и возвращаемые адаптерами значения; для обратных вызовов используется `C.JSObjectRef`.
- Преамбула cgo содержит объявления JavaScriptCore и вспомогательные объявления моста. Для преобразования обратного вызова напрямую используется `JSValueToObject`, а числовое преобразование делегируется `Context`.
- Эти адаптеры не выполняют явную обработку исключений JavaScript или проверку данных помимо описанных выше проверок. Внутреннее состояние таймеров и событий, защита времени жизни обратных вызовов и детали выполнения относятся к `dom_events.go`.
