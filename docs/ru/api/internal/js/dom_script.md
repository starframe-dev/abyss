# API скриптов DOM

Этот файл пакета связывает узлы DOM со значениями JavaScriptCore и выполняет скрипты, найденные в документе DOM. Он также предоставляет доступ к итоговому дереву DOM.

## Публичный API

### `GetFinalDOM`

```go
func GetFinalDOM() *dom.Node
```

Возвращает `rootDoc` — корневой документ уровня пакета после выполнения скриптов. Функция возвращает сохранённый указатель напрямую: она не клонирует дерево и не проверяет значение на nil.

### `ExecuteScripts`

```go
func ExecuteScripts(ctx *Context, doc *dom.Node, baseURL string) error
```

Выполняет скрипты в `doc`, используя `baseURL` для разрешения URL внешних скриптов. Эта вспомогательная функция использует `context.Background`, поэтому вызывающие стороны не могут напрямую отменить операцию. Если требуется отмена или крайний срок, заданный вызывающим кодом, используйте `ExecuteScriptsContext`.

### `ExecuteScriptsContext`

```go
func ExecuteScriptsContext(execCtx context.Context, ctx *Context, doc *dom.Node, baseURL string) error
```

Обрабатывает элементы скриптов в порядке их следования в документе. Устанавливает общий тайм-аут в 30 секунд на основе `execCtx` и соблюдает ограничения для каждой страницы:

- Рассматривается не более 128 элементов скриптов; дополнительные элементы игнорируются.
- Суммарно вычисляется не более 8 МиБ исходного кода скриптов. Длина исходного кода измеряется в байтах. Если следующий скрипт превышает оставшийся лимит, обработка прекращается, а не пропускает этот скрипт и продолжается дальше.

Если у элемента есть непустой атрибут `src`, URL разрешается относительно `baseURL`, затем скрипт загружается и выполняется. В противном случае его текстовое содержимое считается встроенным JavaScript; встроенное содержимое, состоящее только из пробельных символов, пропускается. Скрипты выполняются последовательно.

Ошибки загрузки и выполнения JavaScript намеренно игнорируются, чтобы отдельный проблемный скрипт не приводил к сбою обработки страницы. Ошибка возвращается, если отмена общего контекста или истечение его срока обнаружены в начале итерации. В остальных случаях функция возвращает nil, в том числе если отдельные скрипты завершаются с ошибкой. Нулевой документ или контекст JavaScript не проверяются и не являются допустимыми входными данными.

## Представление DOM в JavaScript

Внутренняя функция `nodeToJS` создаёт обычный объект JavaScriptCore для узла DOM. Она сохраняет внутренний идентификатор узла в `__go_id` и предоставляет `nodeType`, используя стандартные числовые значения DOM для поддерживаемых типов узлов:

| Внутренний тип узла | JavaScript `nodeType` |
| --- | ---: |
| Элемент | 1 |
| Текст | 3 |
| Комментарий | 8 |
| Документ | 9 |
| Фрагмент документа | 11 |

Обёртки элементов дополнительно содержат `tagName`, преобразованный к верхнему регистру из внутреннего имени тега. Обёртки текстовых узлов содержат текст узла в `textContent`. Другие свойства и методы DOM здесь не добавляются. Если `getNodeID` возвращает отрицательный идентификатор, функция возвращает JavaScript `null` вместо объекта-обёртки.

## Загрузка внешних скриптов

Внутренняя функция `fetchScript` устанавливает трёхсекундный тайм-аут, используя фоновый контекст. `fetchScriptContext` разбирает базовый URL и источник как URL, разрешает ссылку источника относительно базового URL, а затем вызывает `fetcher.FetchJS` с трёхсекундным тайм-аутом, заданным на основе переданного родительского контекста. Ошибки разбора URL дополняются контекстом, указывающим, не удалось ли разобрать базовый URL или источник скрипта. При обычном выполнении скриптов ошибки загрузки игнорируются функцией `ExecuteScriptsContext`.

## Примечания по реализации

Значения и свойства JavaScript создаются через C API JavaScriptCore. Временные строки C и ссылки на строки JavaScriptCore, используемые для имён свойств, освобождаются с помощью отложенной очистки. Выполнение скриптов опирается на существующую реализацию `Context.Evaluate`; этот файл не обеспечивает транзакционный откат, отчёт об ошибках для отдельных скриптов или синхронизацию обёрток DOM сверх описанных выше свойств узлов.
