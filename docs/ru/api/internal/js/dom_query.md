# DOM-запросы и обход дерева

В этом файле описаны внутренние вспомогательные функции для запросов к DOM и обхода дерева, реализованные в `internal/js/dom_query.go`. Это непубличные вспомогательные функции Go-пакета, а не общедоступный API Go. Они работают с реестром узлов пакета (`nodes`), идентифицируемых через `NodeID`, и напрямую возвращают значения `*dom.Node`.

## Обзор API

| Вспомогательная функция | Поведение |
| --- | --- |
| `getParentNode(id NodeID) *dom.Node` | Возвращает родительский узел или `nil`, если идентификатор неизвестен. |
| `getChildren(id NodeID) []*dom.Node` | Возвращает срез дочерних узлов или `nil`, если идентификатор неизвестен. |
| `getElementsByTagName(tagName string) []*dom.Node` | Находит зарегистрированные узлы-элементы с совпадающим без учёта регистра именем тега. |
| `getElementsByClassName(className string) []*dom.Node` | Находит зарегистрированные узлы-элементы, атрибут `class` которых содержит точное совпадение среди разделённых пробелами токенов. |
| `querySelector(nodeID NodeID, selector string) *dom.Node` | Возвращает первый узел, соответствующий селектору внутри зарегистрированного узла, либо `nil`, если идентификатор недействителен или совпадений нет. |
| `querySelectorAll(nodeID NodeID, selector string) []*dom.Node` | Возвращает все узлы, соответствующие селектору внутри зарегистрированного узла, либо `nil`, если идентификатор недействителен. |
| `matches(nodeID NodeID, selector string) bool` | Проверяет, соответствует ли зарегистрированный узел селектору; для недействительных идентификаторов возвращает `false`. |
| `closest(nodeID NodeID, selector string) *dom.Node` | Возвращает ближайший подходящий узел согласно `dom.Node.Closest`; для недействительных идентификаторов возвращает `nil`. |
| `cloneNode(nodeID NodeID, deep bool) *dom.Node` | Клонирует зарегистрированный узел, присваивая идентификаторы дереву клона; возвращает `nil` при недействительном входе или достижении ограничений клонирования/регистрации. |
| `contains(parentID, childID NodeID) bool` | Проверяет, содержит ли первый узел второй в своей цепочке родителей; узел содержит сам себя. |
| `previousElementSibling(nodeID NodeID) *dom.Node` | Возвращает ближайший предшествующий соседний элемент, пропуская узлы не-элементы. |
| `nextElementSibling(nodeID NodeID) *dom.Node` | Возвращает ближайший следующий соседний элемент, пропуская узлы не-элементы. |
| `firstElementChild(nodeID NodeID) *dom.Node` | Возвращает первый дочерний элемент, пропуская дочерние узлы не-элементы. |
| `lastElementChild(nodeID NodeID) *dom.Node` | Возвращает последний дочерний элемент, пропуская дочерние узлы не-элементы. |

## Поведение и детали

### Поиск по всему реестру

`getElementsByTagName` и `getElementsByClassName` просматривают реестр `nodes`. Их результаты не ограничены определённым корнем или поддеревом. Учитываются только узлы типа `dom.ElementNode`. Имена тегов сравниваются после преобразования к нижнему регистру как запрошенного имени, так и имени тега каждого узла. Значения классов разбиваются с помощью `strings.Fields`, поэтому любая последовательность пробельных символов разделяет токены; сравнение точное и учитывает регистр.

Эти функции добавляют совпадения в порядке обхода карты Go, который не определён. Вызывающие стороны не должны полагаться на стабильный порядок результатов.

### Операции с селекторами

`querySelector` и `querySelectorAll` делегируют интерпретацию селекторов и обход дерева соответственно методам `dom.Node.QuerySelector` и `dom.Node.QueryAll`. Отсутствующая или nil-запись в реестре приводит к возврату `nil` без делегирования. `matches` и `closest` также делегируют работу методам `dom.Node.Matches` и `dom.Node.Closest` после получения узла. Поэтому синтаксис и поведение селекторов определяются реализацией `internal/dom`, а не этим файлом.

### Клонирование и идентификация

`cloneNode` отклоняет неизвестные или nil-узлы и не начинает работу, если в реестре уже находится не менее `dom.MaxDOMNodes` записей. Он вызывает `n.Clone(deep)`, а при успехе использует `assignIDsToNew` для регистрации идентификаторов клонированного узла (и его потомков — согласно поведению этой вспомогательной функции). Функция возвращает `nil`, если клонирование не удалось или полученный клон отсутствует в `nodeIDs`.

### Обход предков и соседей

`contains` считает одинаковые идентификаторы отношением включения до проверки реестра. В остальных случаях оба идентификатора должны разрешаться в ненулевые узлы, после чего функция проходит по указателям `Parent` дочернего кандидата, пока не достигнет предполагаемого родителя или цепочка не закончится.

Вспомогательные функции для соседей просматривают срез `Children` родителя узла и возвращают только узлы типа `dom.ElementNode`. Функции для первого и последнего дочернего элемента просматривают собственные дочерние узлы в прямом или обратном порядке. Если узел, родитель или подходящий связанный узел отсутствует, возвращается `nil`.

## Синхронизация и владение

Чтение и просмотр реестра защищены с помощью `nodeMu`. Некоторые функции снимают блокировку до обхода связей между узлами или вызова методов DOM (`matches`, `closest`, `contains` и функции для соседних/дочерних элементов). Возвращаемые указатели и срезы ссылаются на базовые объекты DOM; этот файл не создаёт их копии. При использовании этих ссылок вызывающим сторонам следует учитывать правила синхронизации и изменения данных в пакете.
