# Вычисленные значения CSS

`internal/css/computed_values.go` содержит вспомогательные функции преобразования, которые превращают текстовые значения, подобные CSS, в типизированные значения пакета (`Length`, `Color`, `Border` и перечисления макета). Большинство функций не экспортируются и предназначены для использования внутри пакета `css`. Единственный экспортируемый API в этом файле — `Hex`.

## Публичный API

### `Hex(s string) Color`

Разбирает шестнадцатеричный цвет в формате `#RGB` или `#RRGGBB`. Короткие шестнадцатеричные цифры расширяются (например, `#abc` преобразуется в каналы 170, 187 и 204). Если длина неверна, отсутствует `#` или встречаются недопустимые шестнадцатеричные цифры, возвращается `Transparent()`, а не ошибка.

## Поведение парсеров

Все остальные парсеры ниже являются закрытыми для пакета. При неподдерживаемом вводе они обычно выбирают значение по умолчанию или значение-маркер вместо возврата ошибки. Поэтому вызывающим функциям не следует считать возвращённое значение подтверждением корректности ввода.

### Длины и числа

- `parseLength` удаляет пробелы по краям и распознаёт `auto`, `px`, `%`, `rem`, `em`, `fr` и числа без единиц измерения (считаются пикселями).
- `rem` и `em` упрощённо преобразуются в пиксели с фиксированным коэффициентом 16; этот парсер не вычисляет унаследованные или вычисленные размеры шрифта.
- Значения `fr` должны быть неотрицательными. Недопустимые значения и неподдерживаемые единицы измерения возвращают `Auto()`.
- Числовые значения длины отклоняются, если их не удаётся разобрать, а также если это NaN или бесконечность. Конечные значения ограничиваются диапазоном ±1 000 000 (`maxCSSLength`). Результат преобразования `rem`/`em` также ограничивается.
- `parseFloat` применяет ту же политику проверки конечности и ограничения диапазона, возвращая ноль для недопустимого ввода. `parseInt` удаляет пробелы по краям и возвращает ноль, если преобразование не удалось.
- `parseBorderWidth` удаляет суффикс `px` и разбирает число с плавающей точкой, но не применяет проверки диапазона, используемые `parseLength`.

### Блочная модель

`parseBoxModel` принимает от одного до четырёх разделённых пробелами значений длины, используя сокращённую CSS-схему:

| Значения | Верх | Справа | Низ | Слева |
| --- | --- | --- | --- | --- |
| 1 | 1-е | 1-е | 1-е | 1-е |
| 2 | 1-е | 2-е | 1-е | 2-е |
| 3 | 1-е | 2-е | 3-е | 2-е |
| 4 | 1-е | 2-е | 3-е | 4-е |

Любое другое количество токенов возвращает `BoxModel` с нулевыми значениями.

### Цвета

`parseColor` удаляет пробелы по краям и приводит ввод к нижнему регистру. Он распознаёт встроенные имена из `namedColors`, шестнадцатеричные формы, принимаемые `Hex`, и синтаксис `rgb(r, g, b)` с целыми числами через запятую. Неизвестные или некорректные цвета становятся прозрачными. Поддерживаемая таблица именованных цветов намеренно ограничена и не включает полный набор имён цветов CSS.

`parseRgb` требует ровно три целочисленных канала, а также буквальные префикс `rgb(` и суффикс `)`. Значения каналов ограничиваются диапазоном 0–255. Функция внутренне сообщает об успешном разборе; при ошибке `parseColor` возвращает прозрачный цвет.

### Границы

`parseBorder` разделяет сокращённое значение по пробелам. Он распознаёт `none` и `solid` как стили, числовые токены или токены с `px` как ширину, а остальные токены считает цветами. Начальный стиль — `BorderNone`; для нераспознанных цветов используется прозрачное значение, предусмотренное `parseColor`. Поддерживается лишь небольшое подмножество синтаксиса границ CSS, а не полноценный CSS-токенизатор.

`parseBorderStyle` распознаёт только `none` и `solid`; для всех остальных значений используется `BorderNone`.

### Ключевые слова макета и выравнивания

Парсеры ключевых слов возвращают значения перечислений, определённых в других местах пакета `css`, и используют следующие запасные значения:

| Парсер | Распознаваемые значения | Запасное значение |
| --- | --- | --- |
| `parseTextAlign` | `center`; `right`, `end` | left |
| `parseDisplay` | `block`, `inline`, `inline-block`, `inline-box`, `flex`, `-webkit-flex`, `-webkit-box`, `grid`, `none` | block |
| `parsePosition` | `static`, `relative`, `absolute` | static |
| `parseOverflow` | `hidden`, `visible` | visible |
| `parseFlexDirection` | `row`, `column` | row |
| `parseJustifyContent` | `flex-start`, `center`, `flex-end`, `space-between`, `space-around` | flex-start |
| `parseAlignItems` | `flex-start`, `center`, `flex-end`, `stretch` | stretch |

Только `parseTextAlign` нормализует регистр и пробелы по краям. Остальные парсеры ключевых слов используют точное сопоставление строк.

### Списки дорожек сетки

`parseLengthList` разбирает токены длины, разделённые пробелами или запятыми, и поддерживает простую форму `repeat(count, item)`, повторяя элемент `count` раз. Результат ограничен `maxGridTracks` (256) элементами. Число повторов должно быть положительным целым; некорректные или неположительные значения не добавляют элементов. Если конструкция `repeat(` не закрыта, разбор оставшейся части ввода прекращается. Каждая полученная дорожка разбирается через `parseLength`, поэтому недопустимые дорожки становятся `Auto()`.

## Примечания к реализации

- Эти функции намеренно возвращают детерминированные запасные значения, а не ошибки; проверка полной грамматики CSS не входит в их задачи.
- `namedColors` и все вспомогательные функции парсеров — закрытые детали реализации. Используемые ими перечисления и конструкторы значений определены в других местах пакета.
- `isNumber` — простой предикат на основе `strconv.ParseFloat`, используемый при разборе границ; в отличие от `parseFloat`, он явно не отклоняет NaN и бесконечность.
