# Парсер CSS

Пакет `css` предоставляет лёгкие вспомогательные функции для разбора встроенных стилей и таблиц стилей CSS, а также простую оценку специфичности селектора. Это намеренно ограниченный парсер, а не полноценная реализация CSS.

## Публичный API

### `Declaration`

Представляет одну разобранную пару свойство/значение.

| Поле | Тип | Значение |
| --- | --- | --- |
| `Property` | `string` | Имя свойства без окружающих пробелов. |
| `Value` | `string` | Значение без окружающих пробелов и распознанного суффикса `!important`. |
| `Important` | `bool` | Указывает, заканчивалось ли значение на `!important` (регистр не учитывается). |

### `Rule`

Представляет список селекторов и их объявлений, возможно вложенных в поддерживаемые условия.

| Поле | Тип | Значение |
| --- | --- | --- |
| `Selectors` | `[]string` | Селекторы, разделённые запятыми и очищенные от окружающих пробелов по отдельности. |
| `Declarations` | `[]Declaration` | Объявления, разобранные из блока правила. |
| `MediaQuery` | `string` | Накопленный внешний запрос `@media` или пустая строка. |
| `SupportsQuery` | `string` | Накопленный внешний запрос `@supports` или пустая строка. |

### `ParseInline(style string) []Declaration`

Разбирает строку атрибута style на объявления. Сегменты, разделённые точками с запятой и не содержащие двоеточия, игнорируются; первое двоеточие разделяет свойство и значение. Пустые сегменты пропускаются. Скобки защищают точки с запятой от разделения, поэтому значения функций, например `url(...)` или `var(...)`, остаются целыми.

### `ParseStyleSheet(css string) []Rule`

Удаляет блочные комментарии и разбирает обычные правила, а также правила, вложенные в блоки `@media` и `@supports`. Вложенные условия объединяются через ` and ` в соответствующих полях. Неподдерживаемые директивы пропускаются вместе с их содержимым; разбор некорректных или незавершённых блоков останавливается, если невозможно найти соответствующую закрывающую фигурную скобку. Рекурсия ограничена 32 уровнями вложенности директив.

### `Specificity(selector string) int`

Возвращает взвешенную приблизительную оценку специфичности: `100` за каждый идентификатор, `10` за каждый класс, селектор атрибута или псевдокласс и `1` за каждый селектор типа или псевдоэлемент. Это оценка для сортировки, а не полный кортеж специфичности CSS; она не реализует все современные правила селекторов.

## Особенности и ограничения разбора

- Пробелы вокруг имени свойства и значения объявления удаляются. Завершающий регистронезависимый `!important` удаляется и отражается в `Important`.
- Селекторы таблицы стилей разделяются непосредственно по запятым; запятые внутри функциональных псевдоклассов специально не защищаются.
- При поиске парных фигурных скобок учитываются вложенные скобки, строки в кавычках, экранирование обратной косой чертой и круглые скобки. Полная грамматика токенов CSS не разбирается.
- При удалении комментариев распознаются последовательности `/* ... */` без учёта того, находятся ли маркеры внутри строк в кавычках.
- При разделении объявлений отслеживается глубина круглых скобок, но не кавычки и экранированные символы. Двоеточия разделяются по первому буквальному двоеточию.
- При разборе специфичности учитываются пробелы и комбинаторы `>`, `+` и `~`, а эти символы внутри квадратных скобок атрибутов сохраняются. Экранированные идентификаторы и семантика специфичности функциональных псевдоклассов моделируются не полностью.
- Пустой ввод и неразбираемые фрагменты дают пустой результат или пропускаются, а не возвращают ошибки; API не предоставляет диагностические сообщения.

## Внутренняя реализация

`parseRules` вызывает `parseRulesInMedia`, которая ищет открывающие фигурные скобки, находит соответствующие закрывающие скобки и рекурсивно обрабатывает поддерживаемые условные директивы. `stripImportant`, `splitBySemicolon` и вспомогательные функции для скобок и селекторов реализуют примитивы разбора. Всё состояние парсера локально для каждого вызова; изменяемого состояния уровня пакета нет.
