# Вычисленные стили CSS

`internal/css/computed.go` вычисляет поддерживаемое подмножество вычисленных стилей CSS для узлов DOM. Файл собирает правила таблиц стилей, сопоставляет их с элементами, применяет каскад, разрешает пользовательские свойства и возвращает карту стилей с указателями на узлы в качестве ключей.

## Публичный API

| Функция | Поведение |
| --- | --- |
| `Compute(doc *dom.Node) map[*dom.Node]ComputedStyle` | Вычисляет стили при ширине `0`, без внешнего CSS. |
| `ComputeAtWidth(doc *dom.Node, viewportWidth float64) map[*dom.Node]ComputedStyle` | Вычисляет стили для заданной ширины области просмотра в CSS-пикселях. |
| `ComputeWithExternal(doc *dom.Node, externalCSS []string) map[*dom.Node]ComputedStyle` | Вычисляет стили с дополнительными строками CSS при ширине `0`. |
| `ComputeWithExternalAtWidth(doc *dom.Node, externalCSS []string, viewportWidth float64) map[*dom.Node]ComputedStyle` | Объединяет внешний CSS и ширину области просмотра. |
| `InvalidateCache()` | Очищает кэш вычисленных стилей пакета. Вызывайте после изменений DOM, внесённых JavaScript. |

Возвращённая карта связывает указатель каждого посещённого узла DOM с его `ComputedStyle`. Этот файл не определяет экспортируемых типов; `ComputedStyle` и типы правил и парсеров определены в другом месте пакета `css`.

## Вычисление и каскад

Реализация собирает CSS из каждого элемента `<style>`, найденного с помощью `FindStyleTags`. Если атрибут `media` не пуст, текст этого элемента оборачивается в правило `@media` перед разбором. Каждая строка внешнего CSS разбирается и добавляется после встроенных правил.

Обход DOM выполняется рекурсивно. Каждый узел начинает с `Default()`; если у родителя доступен `Color`, он копируется. Пользовательские свойства клонируются у родителя, чтобы потомки наследовали их, не изменяя карту переменных родителя. Перед применением правил проверяются условия media и supports, а затем каждый подходящий селектор добавляет декларации правила. Также учитываются встроенные декларации, разобранные из атрибута узла `style`.

Декларации стабильно сортируются от меньшего приоритета к большему: сначала без `!important`, затем с ним; сначала не встроенные, затем встроенные; сначала с меньшей специфичностью селектора, затем с большей. Стабильный порядок сохраняет порядок исходного кода при равенстве приоритетов. Пользовательские свойства собираются в порядке каскада до применения обычных деклараций, что позволяет `var()` ссылаться на пользовательское свойство, объявленное позже в исходном порядке. Имена пользовательских свойств приводятся к нижнему регистру, а окружающие пробелы удаляются. Обычные декларации обрабатываются через `applyDeclaration`, которая направляет поддерживаемые свойства соответствующим парсерам и обновляет нужные поля `ComputedStyle`.

Поддерживаемые группы свойств включают отступы блочной модели и внутренние поля, границы и радиусы, размеры и списки дорожек сетки, позиционные смещения, цвета текста и фона, а также свойства макета, такие как display, position, overflow, z-index, выравнивание текста и отдельные настройки flex. Неподдерживаемые свойства игнорируются функциями диспетчеризации.

## Обработка селекторов и условий

С селекторами сопоставляются только узлы-элементы. `:root` обрабатывается особым образом и соответствует элементу, родителем которого является узел документа. Пустой селектор считается соответствующим любому элементу; остальные селекторы передаются в `dom.Node.Matches`.

Длина медиазапросов ограничена 256 символами. Пустые запросы считаются подходящими; варианты, разделённые запятыми, объединяются логическим ИЛИ. Реализация распознаёт `all`, `screen`, необязательное `only`, `screen and ...`, `all and ...`, а также заключённые в скобки условия `min-width`/`max-width` в `px`. `print`, `not ...`, некорректные условия, неподдерживаемые имена условий и неразбираемые значения не подходят. Все ограничения ширины в одном варианте должны выполняться.

Длина условий supports также ограничена 256 символами. Обработчик поддерживает `or`, `and`, `not`, необязательные внешние скобки и проверки свойства и значения для ограниченного набора значений `display` (`block`, `inline`, `flex`, `grid`, `none`) и `position` (`static`, `relative`, `absolute`). Неизвестные или некорректные проверки не проходят.

## Пользовательские свойства

Ссылки `var()` разрешаются рекурсивно, без учёта регистра имени переменной, и поддерживают запасное значение, отделённое запятой. Для отсутствующей переменной или циклической ссылки используется запасное значение, если оно есть; иначе разрешение завершается ошибкой, а всё значение обычного свойства становится пустой строкой. Глубина разрешения ограничена `maxVariableResolutionDepth` (64); некорректные скобки и чрезмерная рекурсия также приводят к ошибке. Значения без токена `var(` возвращаются без изменений.

## Кэш и конкурентный доступ

Мьютекс уровня пакета защищает единственный указатель кэшированного документа, карту стилей и ширину области просмотра. Результат используется повторно, только если совпадают указатель документа и ширина, кэш заполнен и внешний CSS не был передан. Вычисления с внешним CSS всегда выполняются заново, но их результат всё равно сохраняется в кэше и поэтому впоследствии может быть использован вызовом без внешнего CSS для того же документа и ширины. Изменения DOM автоматически не обнаруживаются; чтобы избежать устаревших результатов, вызывающий код должен использовать `InvalidateCache`. Кэш одновременно хранит результаты только для одного документа.

Мьютекс сериализует проверки кэша и полное вычисление. Реализация предполагает, что документ не равен nil, и не сообщает об ошибках; разбор и неподдерживаемые значения обрабатываются существующим поведением парсеров, а не возвращаются как ошибки.
