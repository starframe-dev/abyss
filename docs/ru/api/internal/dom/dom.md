# `internal/dom`

Пакет `dom` строит и изменяет облегчённое дерево, подобное DOM, из HTML. Для токенизации он использует `golang.org/x/net/html`, а затем применяет собственные правила построения дерева, делегирования селекторов и сериализации. Это упрощённое представление, а не полноценный DOM браузера или реализация построения дерева HTML5.

## Разбор

```go
func Parse(htmlStr string) *Node
func ParseFragment(htmlStr string) *Node
```

`Parse` возвращает корень `DocumentNode`; `ParseFragment` возвращает корень `DocumentFragmentNode`, не добавляя обёртку-элемент. Обе функции инициализируют пустые коллекции атрибутов и дочерних узлов и используют один и тот же ограниченный токенизатор.

При достижении лимита разбор сохраняет безопасно построенный префикс. Экспортируемые ограничения:

| Константа | Значение | Описание |
| --- | ---: | --- |
| `MaxDOMNodes` | 100000 | Максимальное число учитываемых узлов, включая корень |
| `MaxDOMDepth` | 512 | Максимальная глубина стека, включая корень |

Максимальный размер буфера токенаизатора — 1 МиБ. Ошибка токенизатора (включая некорректный ввод или слишком большой токен) останавливает разбор и возвращает уже построенное дерево. Текстовые токены, состоящие только из пробельных символов, обычно отбрасываются, кроме случаев внутри элемента `pre` или когда предыдущий дочерний узел — элемент. Это сохраняет пробелы между соседними элементами, отсекая большую часть форматирующих пробелов.

Парсер распознаёт пустые HTML-элементы (`area`, `base`, `br`, `col`, `embed`, `hr`, `img`, `input`, `keygen`, `link`, `meta`, `param`, `source`, `track` и `wbr`) и не помещает их в стек открытых элементов. Он также выполняет ограниченное неявное закрытие абзацев, элементов списков, терминов и описаний определений, вариантов, ячеек, строк и секций таблиц, а также заголовков. Это восстановление намеренно более ограниченное, чем разбор HTML в браузере. Имена атрибутов приводятся к нижнему регистру; значения сохраняются в том виде, в каком их возвращает токенизатор.

## Модель данных

### `NodeType`

`NodeType` — целое число, обозначающее тип узла:

| Константа | Значение | Описание |
| --- | ---: | --- |
| `ElementNode` | 1 | Элемент |
| `TextNode` | 3 | Текст |
| `CommentNode` | 8 | Комментарий |
| `DocumentNode` | 9 | Корень документа |
| `DocumentFragmentNode` | 11 | Корень фрагмента |

### `Node`

```go
type Node struct {
    Type       NodeType
    TagName    string
    Attributes map[string]string
    Children   []*Node
    Text       string
    Parent     *Node
}
```

Поля экспортируются и доступны для непосредственного изменения. У элементов, созданных при разборе, имя тега в нижнем регистре, карта атрибутов и срез дочерних узлов. Для разобранных дочерних узлов устанавливаются указатели на родителя. Текстовые узлы хранят содержимое в `Text`. У корней документа и фрагмента родителя нет. При непосредственном изменении дерева вызывающий код отвечает за согласованность связей между дочерними узлами и родителями.

## Селекторы и обход

```go
func (n *Node) QueryAll(selector string) []*Node
func (n *Node) QuerySelector(selector string) *Node
func (n *Node) Matches(selector string) bool
func (n *Node) Closest(selector string) *Node
```

Эти методы делегируют проверку селекторов функциям `QueryAllSelector`, `QuerySelectorSelector` и `MatchesSelector` пакета. `QueryAll` возвращает совпавшие потомки; `QuerySelector` — первый совпавший потомок или `nil`. `Closest` сначала проверяет сам узел, затем проходит по родителям и возвращает ближайшее совпадение или `nil`; для получателя `nil` он безопасно возвращает `nil`. Поддерживаемый синтаксис селекторов определяется этими вспомогательными функциями.

```go
func (n *Node) FindStyleTags() []*Node
func (n *Node) FindLinkStylesheets() []*Node
```

`FindStyleTags` выбирает элементы `style`. `FindLinkStylesheets` выбирает элементы `link[rel=stylesheet]`.

## Атрибуты и изменение дерева

```go
func (n *Node) GetAttr(name string) string
func (n *Node) RemoveChild(child *Node) *Node
func (n *Node) AppendChild(child *Node) *Node
func (n *Node) Clone(deep bool) *Node
```

- `GetAttr` приводит запрошенное имя к нижнему регистру и возвращает его значение либо `""`, если карта равна `nil` или ключ отсутствует. Поэтому отсутствующий атрибут и атрибут с явно пустым значением неразличимы.
- `RemoveChild` удаляет первого дочернего узла, указатель на который равен `child`, очищает указатель этого узла на родителя и возвращает его. Если узел не найден, возвращает `nil`.
- `AppendChild` добавляет переданный указатель, задаёт его родителем получателя и возвращает дочерний узел. Метод не отсоединяет его от прежнего родителя и не проверяет циклы; эти инварианты должен обеспечивать вызывающий код.
- `Clone(false)` копирует тип, тег, текст и атрибуты узла, но не дочерние узлы и не родителя. `Clone(true)` рекурсивно копирует потомков и устанавливает их указатели на соответствующие копии-родители. В обоих случаях карты атрибутов независимы.

## Текст и сериализация

```go
func (n *Node) TextContent() string
func (n *Node) OuterHTML() string
```

`TextContent` объединяет текст потомков в порядке следования. Текстовый узел возвращает непосредственно собственное поле `Text`; остальные типы узлов объединяют дочерние узлы и не включают собственное поле `Text`.

`OuterHTML` возвращает пустую строку для получателя `nil`. Узлы документа и фрагмента сериализуются как объединение дочерних узлов без обёртки. Текстовые узлы и узлы-комментарии сериализуются как обычный текст с экранированием содержимого `Text`; маркеры комментариев не выводятся. Элементы сериализуются с тегом, атрибутами, содержимым и закрывающим тегом. Порядок атрибутов при обходе карты Go не определён, поэтому порядок сериализованных атрибутов не гарантируется. В тексте и значениях атрибутов экранируются `&`, `<`, `>` и `"`.

Пустой элемент, распознаваемый как пустой, сериализуется в виде `<tag />`; список пустых элементов сериализатора не содержит `keygen`, хотя список парсера его содержит. Непустые элементы всегда получают закрывающий тег. Поскольку при разборе поле `Text` элементов не заполняется, их содержимое обычно формируется дочерними узлами; вручную заданное непустое значение `Text` сериализуется перед дочерними узлами.

## Примечания

Пакет предоставляет компактное изменяемое дерево, а не DOM, полностью соответствующий стандартам. В частности, восстановление при разборе ограничено, комментарии при сериализации не получают синтаксис HTML-комментариев, а вывод сериализатора является представлением дерева, а не точным обратным преобразованием исходного текста.
