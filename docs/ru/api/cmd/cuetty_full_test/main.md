# `cmd/cuetty_full_test`

## Обзор

Этот пакет Go `main` представляет собой ручной исполняемый файл для сквозного дымового тестирования терминального приложения Abyss. Он запускает `./bin/abyss` в эмулируемом терминале с помощью API управления тестами `github.com/starframe-dev/cue-tty/pkg/cue`, имитирует ввод с клавиатуры, проверяет отображаемый текст терминала и завершается с ненулевым кодом, если обязательное поведение не соблюдается.

Запускайте его из контекста репозитория, где существует `./bin/abyss`, а текущий каталог является целевым рабочим каталогом. Параметры терминала: 120 столбцов и 40 строк, `TERM=xterm-256color`.

## Публичный API

Экспортируемого API библиотеки нет. Пакет предоставляет только точку входа программы Go:

| Символ | Описание |
| --- | --- |
| `main()` | Запускает приложение, последовательно выполняет сценарии дымового тестирования, выводит результаты в стандартный вывод и завершает процесс при сбое. |

Исполняемый файл использует пакет `cue`: функцию `Launch`, параметры запуска, методы взаимодействия со страницей и вспомогательные функции проверок. Здесь они используются, но данный файл не определяет их реализацию или дополнительные публичные типы.

## Последовательность тестирования

1. **Начальный экран:** запускает Abyss и ожидает стабильного экрана не более двух секунд. Выводит отображаемый текст и проверяет наличие `Abyss` и `Enter URL`.
2. **Переход:** вводит `example.com`, ненадолго ожидает, нажимает Enter и ждёт до 15 секунд появления `Example Domain`. Затем проверяет и выводит текст загруженной страницы.
3. **Прокрутка:** сохраняет содержимое экрана, восемь раз нажимает Down, ожидает стабильного состояния и завершается с ошибкой, если отображаемый текст не изменился.
4. **Обновление:** нажимает `r`, ожидает не более двух секунд и проверяет, что `Example Domain` по-прежнему отображается.
5. **Страница ошибки:** нажимает Escape, вводит `not-a-valid-url-12345.xyz`, отправляет адрес, ждёт до десяти секунд появления `Error:` и проверяет этот маркер.
6. **Выход:** нажимает `q`, ненадолго ожидает, явно закрывает приложение и проверяет успешность закрытия.

При успешном завершении после сообщений об отдельных сценариях выводится `ALL TESTS PASSED`.

## Обработка ошибок и ресурсов

При ошибке запуска, неудачной проверке или сбое при выходе/закрытии в стандартный поток ошибок выводится сообщение `FAIL:`, после чего вызывается `os.Exit(1)`. После успешного запуска регистрируется `defer app.Close()` для очистки; явное закрытие в сценарии выхода также проверяется, а при возврате из `main` затем вызывается отложенное закрытие. Поскольку `os.Exit` немедленно завершает процесс, при сбоях, приводящих к его вызову, отложенные функции не выполняются.

Вызовы, получающие текст терминала, отбрасывают возвращаемую ошибку (`page.Text()` использует `text, _`). Поэтому тест считает полученный текст пригодным к использованию и отдельно не сообщает об ошибках получения текста. Интервалы и ожидания заданы фиксированно и не настраиваются, поэтому это дымовой тест, поведение которого зависит от наличия исполняемого файла и завершения сетевой навигации в пределах указанного тайм-аута.
