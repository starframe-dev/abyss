# `cmd/render_test`

`cmd/render_test` — команда только для разработки, которая загружает веб-страницу и отображает её в виде текстовой графики с ANSI-цветами. Она предназначена для проверки ASCII-рендерера изображений и записывает цветные и обычные текстовые фикстуры в `/tmp`.

## Использование

```sh
go run ./cmd/render_test <url> [width]
```

- `<url>` — обязательный параметр, передаваемый загрузчику проекта.
- `[width]` — необязательная целочисленная ширина рендеринга; значение по умолчанию — `120`.
- Если URL не указан, команда выводит справку по использованию в стандартный поток ошибок и завершает работу с кодом `2`.
- При ошибке загрузки страницы сообщение выводится в стандартный поток ошибок, а команда завершается с кодом `1`.

Необязательная ширина разбирается с помощью `fmt.Sscanf`; ошибка игнорируется. Поэтому при недопустимом значении используется ширина по умолчанию либо значение, частично разобранное `Sscanf`.

## Обработка

Команда выполняет следующие действия:

1. Инициализирует локальный для процесса кэш изображений и устанавливает `render.ImageProvider`, который возвращает изображения из кэша или `nil` при промахе.
2. Загружает страницу с помощью `fetcher.Fetch` и разбирает HTML в DOM.
3. Находит элементы `<img>`, разрешает и устраняет дубликаты их источников, загружает или декодирует поддерживаемые данные изображений и сохраняет успешно декодированные изображения в кэше.
4. Вычисляет CSS, строит макет с заданной шириной, выполняет рендеринг и преобразует буфер кадра в вывод ANSI.
5. Записывает вывод ANSI в `/tmp/img_fixture_ansi.txt`, а версию без ANSI escape-последовательностей и с удалёнными конечными пробелами в каждой строке — в `/tmp/img_fixture_plain.txt`.
6. Выводит пути к файлам и каждую непустую строку обычного текста с её индексом, начиная с нуля.

Ошибки при получении и декодировании изображений, а также при записи фикстур намеренно игнорируются. Поэтому неудачно обработанные изображения не попадают в кэш, а ошибки записи не прерывают команду и не меняют её итоговый код завершения.

## Подробности обработки изображений

Значения источников изображений обрезаются по краям; пустые значения пропускаются. Источники `data:` используются как есть, остальные передаются в `resolveURL`. Строки разрешённых источников-дубликатов загружаются или декодируются только один раз за запуск.

Только для URL данных с точным префиксом `data:image/png;base64,` используется специальный путь декодирования base64. Остальные источники загружаются с помощью `fetcher.FetchBytes` и декодируются функцией `asciirender.Decode`. Ключом кэша служит строка разрешённого источника. `sync.RWMutex` защищает доступ к кэшу, в том числе чтение, выполняемое callback-функцией провайдера рендерера.

`resolveURL` возвращает абсолютные значения `http://` и `https://` без изменений. Для пути, начинающегося с косой черты, функция объединяет базовый URL и путь; для остальных относительных значений она возвращает базовый URL без изменений. Этот вспомогательный метод не выполняет полноценное разрешение URL.

## Функции и состояние

Все объявления являются закрытыми в пределах пакета; эта команда не предоставляет публичного Go API.

| Имя | Назначение |
| --- | --- |
| `main()` | Разбирает аргументы и координирует загрузку, разбор, подготовку изображений, рендеринг и вывод фикстур. |
| `fetchImages(doc, baseURL)` | Собирает источники изображений из DOM, загружает поддерживаемые изображения и заполняет кэш. |
| `resolveURL(base, rel)` | Выполняет ограниченную обработку URL источников изображений, предусмотренную командой. |
| `decodeBase64PNG(b64)` | Декодирует данные PNG в формате base64 и передаёт их для декодирования в `asciirender.Decode`. |
| `decodeBase64(s)` | Декодирует base64 с использованием стандартного алфавита и `encoding/base64`. |
| `stripANSI(s)` | Удаляет из строки поддерживаемые ANSI SGR escape-последовательности для текстовой фикстуры. |
| `imageCache` | Сопоставляет строки источников с декодированными значениями `image.Image`. |
| `imageCacheMu` | Мьютекс для чтения и записи, защищающий `imageCache`. |

`stripANSI` распознаёт escape-последовательности, начинающиеся с ESC, за которым следует `[` и числовые параметры или параметры с точками с запятой, и заканчивающиеся на `m`. Другие последовательности с префиксом ESC пропускаются согласно побайтовому парсеру; это не универсальный фильтр управляющих последовательностей терминала.
