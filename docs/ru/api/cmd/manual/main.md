# `cmd/manual`

`cmd/manual` — отдельный исполняемый файл Go, запускающий встроенную демонстрацию интеграции HTML, JavaScript, CSS, компоновки, рендеринга и вывода ASCII в Abyss. Это команда для ручного запуска и демонстрации, а не переиспользуемый пакет библиотеки; пакет не предоставляет экспортируемого API.

## Поток выполнения

При запуске `main`:

1. Записывает встроенный HTML-код `testPage` в файл `abyss_test_page.html` во временном каталоге операционной системы, выводит его путь и планирует удаление с помощью `defer`. При ошибке записи вызывает панику.
2. Разбирает страницу с помощью `dom.Parse` и выводит число дочерних узлов корня разобранного документа.
3. Создаёт контекст JavaScript и планирует вызов `Close` при возврате. Инициализирует мост DOM для JS на основе разобранного документа и направляет журналы JS в стандартный поток ошибок.
4. Регистрирует функции моста и выполняет загрузочный скрипт API DOM. При любой из этих ошибок сообщает о ней в стандартный поток вывода и завершает процесс с кодом 1.
5. Выполняет скрипты документа. Ошибка выполнения скрипта выводится, но не приводит к немедленному завершению команды.
6. Получает итоговый DOM. Если он не равен `nil`, выводит сводку конечного дерева.
7. Вычисляет CSS, строит компоновку шириной 800, выполняет рендеринг в буфер кадра шириной 800, преобразует его в строки ANSI и выводит размеры и строки результата.
8. Приостанавливает выполнение на две секунды, чтобы результат можно было рассмотреть.

## Встроенная тестовая страница

Константа `testPage` — автономный HTML-образец со встроенными CSS и JavaScript. Стили проверяют flex- и grid-компоновку, интервалы, границы, цвета и скруглённые углы. Скрипт проверяет функцию журналирования моста и операции DOM, включая создание элементов, текстовое содержимое, имена и списки классов, встроенные стили, атрибуты, доступ к родительским и дочерним узлам, `innerHTML`, `document.write`, поиск по идентификатору и имени тега, а также удаление дочерних узлов. Он также выводит выбранные результаты и перехватывает ошибки при нескольких проверках API. Тело страницы содержит цветные блоки, ячейки сетки и карточки для визуального рендеринга.

## Функции

### `main()`

Точка входа исполняемого файла и оркестрация, описанная выше. Для вывода этапов выполнения, ошибок, сводок DOM и отрендеренных строк используется стандартный поток вывода; журналы JavaScript направляются в стандартный поток ошибок. Для рендеринга используется фиксированная ширина области просмотра 800. У команды нет флагов и аргументов.

### `printDOMTree(root *dom.Node)`

Выводит каждый дочерний элемент `root`, его тег и число дочерних узлов. Для элемента с именем `html` дополнительно вызывает `printHTMLBody`. Дочерние узлы корня, не являющиеся элементами, игнорируются. Это вспомогательная диагностическая функция, а не экспортируемый API пакета.

### `printHTMLBody(htmlEl *dom.Node)`

Находит непосредственные дочерние элементы `body` переданного HTML-узла и выводит непосредственные дочерние узлы каждого `body`. Для элементов выводятся имя тега, атрибут `class` и результат `TextContent()`. Текстовые узлы обрезаются по краям и укорачиваются до 40 символов; если текст длиннее, в конце добавляется многоточие. Остальные типы узлов пропускаются. Эта вспомогательная функция предполагает, что DOM-узел и его карта атрибутов пригодны к использованию согласно представлению пакета `internal/dom`.

## Зависимости и границы

Команда напрямую объединяет внутренние пакеты: `internal/dom` разбирает и представляет документ; `internal/js` инициализирует и выполняет встроенный скрипт; `internal/css` вычисляет стили; `internal/layout` строит блоки; `internal/render` создаёт буфер кадра; `internal/ascii` преобразует результат в строки для терминала. Это внутренние зависимости проекта, а не публичные API `cmd/manual`.

Временный HTML-файл записывается с правами `0644` и удаляется при нормальном возврате из функции. Очистка контекста JavaScript также отложена. Ошибки моста или загрузочного скрипта обрабатываются вызовом `os.Exit(1)`, который немедленно завершает процесс и поэтому не выполняет отложенную очистку, зарегистрированную в `main`; ошибки выполнения скрипта, напротив, позволяют продолжить последующие этапы рендеринга.
